# 能力声明

**批次结项**：归集产出物、执行断链检测、回填索引、生成结项报告，并把批次状态文件终态化。

**它同时是 gate-06 的产出方。** 此前 gate-06 检查的几项（状态终态化、产出物齐备、结项报告）
在流程里没有负责人——本 Skill 补上这一环。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 批次状态文件 | `.ai/state/<批次号>.yaml` | 是 | 各 steps 已终态；gate-05 已 passed/waived |
| 功能编号总表 | `.ai/index/功能编号总表.md` | 是 | 含本批次的 REQ / FN / TC |
| 全部产出物 | 项目文档仓 `docs/` | 是 | 已登记在状态文件的 `artifacts` |
| 测试报告 | `ai-test-05-report` 产出 | 是 | 含上线建议 |
| 上线步骤 | `ai-iteration-04-release` 产出 | 是（gate-06 前置） | 含回滚方案 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 结项报告 | 项目文档仓 `docs/05_交付/结项报告.md` | 按 `templates/批次结项报告模板.md` |
| 断链检测结果 | 结项报告「三、断链检测」节 + `.ai/index/功能编号总表.md` 断链视图 | 五类断链的计数与明细 |
| 索引回填 | `.ai/index/功能编号总表.md` | 功能点段的「批次」「提交」「覆盖用例」列 |
| 终态化状态文件 | `.ai/state/<批次号>.yaml` | `archived: true` + 归档时间 |

## 前置条件（不满足则拒绝执行）

- gate-05 状态为 `passed` 或 `waived`
- 所有 steps 为终态（`done` / `skipped` / `failed`），无 `in_progress`
- 状态文件记录了 `spec_snapshot.hash`（回答"这个批次用的是哪版规范"）
- `ai-gate-runner` 已实现

## 执行步骤

1. **先跑 gate-06**，不手工判断：
   ```bash
   S=07_质量门禁/skills/ai-gate-runner/scripts/gate_run.py
   python3 $S --project <项目码> --batch <批次号> --gate gate-06
   ```
   自动检查项交给执行器；人工项原样列出，**不代替人判断**。结果为 `failed` 就停下。
2. **执行断链检测**（五类，见 `00_工作空间配置/命名与编号规范.md` 第 9 节）：
   | 类型 | 判据 |
   |---|---|
   | 无 REQ 来源的 FN | 总表「来源 REQ」列空 |
   | 无设计章节的 FN | 该 FN 未出现在设计类产出物中 |
   | 无测试用例覆盖的 FN | 该 FN 没有挂载的 `TC` |
   | 无对应提交的 FN | 该 FN 未出现在任何提交信息中 |
   | 孤儿编号 | 总表有登记但无任何产出物引用 |
3. **回填总表**：「覆盖用例」「提交」「批次」三列。这三列此前由谁填没有定义——本 Skill 负责。
4. 生成结项报告：批次概览、交付内容、断链结果、门禁记录、豁免记录、遗留问题、本批次产生的规则。
5. 把状态文件置 `archived: true` 并记录归档时间。
6. 提示运行 `ai-spec-promote` 分析本批次产生的项目特有条目。

## 边界（明确不做）

- **不修改产出物内容**，只核对存在性与哈希
- **不补链**。断链意味着缺文档或缺用例，那是人的工作——脚本只能把断链指出来并定位
- 不删除任何文件（含 `.ai/state/` 下已归档的状态文件）
- **不在断链非 0 时静默归档**（BLOCK 类非 0 直接拒绝）
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| gate-06 `failed` | 停止，输出未通过项与定位；**不尝试绕过** |
| 断链数 > 0（BLOCK 类：无 REQ 来源 / 无设计章节 / 无用例覆盖） | **拒绝归档**，列出断链明细与定位 |
| 断链数 > 0（WARN 类：无提交 / 孤儿编号） | 归档，但写入结项报告的「遗留问题」节 |
| 产出物缺失或哈希不一致 | 拒绝归档，提示"产出物被外部修改"，由人决定是否重跑上游 |
| 状态文件有 `in_progress` 步骤 | 拒绝归档，提示先处理该步骤 |
| 项目仓不是 git 仓库 | 提交类断链无法判定——**明确记为「未校验」而不是 0**（这一点执行器也会说） |

## 为什么归档值得单独一步

跳过归档的代价是**追溯链断在最后一步**：功能上线了，但没人能回答"它完整走完了哪些环节"。

更实际的两个作用：

| 产出 | 谁在用 |
|---|---|
| 总表回填的「提交」列 | `fn-has-commit` 检查项、后续迭代的影响面分析 |
| 结项报告的「遗留问题」节 | 下个批次接手的人——**这是唯一记录"当时已知但没解决"的地方** |

## 与其他 Skill 的关系

- 上游：`ai-test-05-report`、`ai-iteration-04-release`
- 下游：无（批次在这一步闭环）；后续该系统的改动走 `05_迭代开发` 的变更子批次
- 依赖：`ai-gate-runner`（gate-06）
