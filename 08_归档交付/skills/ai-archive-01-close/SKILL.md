# 能力声明

批次结项：归集产出物、执行断链检测、更新索引、生成结项报告，并把批次状态文件终态化。

**不做**：不做上线部署、不做发布说明（那是 `ai-iteration-04-release` 的职责）。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 批次状态文件 | `.ai/state/<批次号>.yaml` | 是 | 全部 steps 为终态，gate-05 已通过 |
| 功能编号总表 | `.ai/index/功能编号总表.md` | 是 | 存在 |
| 全部产出物 | 项目文档仓 | 是 | 按状态文件的 `artifacts` 段逐项核对 |
| 依赖关系图 | `.ai/index/依赖关系图.md` | 否 | 存在则用于交叉校验 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 结项报告 | 项目文档仓 `docs/04_交付/结项报告.md` | 按 `templates/批次结项报告模板.md` |
| 断链检测结果 | 批次状态文件 `artifacts` + `.ai/index/功能编号总表.md` 断链视图 | Markdown 表格 |
| 终态化的状态文件 | `.ai/state/<批次号>.yaml` | 归档后**只读**，不得删除 |
| 索引更新 | `.ai/index/功能编号总表.md` | 回填批次号列 |

## 前置条件（不满足则拒绝执行）

- gate-05 状态为 `passed` 或 `waived`
- 批次状态文件中所有 steps 为终态（`done` / `skipped` / `failed`），无 `in_progress`
- 本次批次的生效规范快照哈希已记入状态文件

## 执行步骤

1. 核对 `artifacts` 段列出的产出物是否全部存在，且哈希未变
2. 执行**断链检测**（五类，见 `命名与编号规范.md` 第 9 节）
3. 回填 `.ai/index/功能编号总表.md` 的批次列
4. 生成结项报告，含：批次概览、FN 清单、断链结果、豁免记录、遗留问题
5. 把状态文件置为归档态（`archived: true`）并记录归档时间
6. （可选）提示运行 `ai-spec-promote` 分析本批次产生的项目特有条目

## 边界（明确不做）

- **不修改产出物内容。** 只核对存在性与哈希
- 不删除任何文件（含 `_archive/` 之外的历史文件）
- 不做 git 操作
- 不在断链未清零时"自动补链"——补链意味着补文档，那是人的工作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 断链数 > 0（BLOCK 类） | 拒绝归档，列出断链明细与定位 |
| 断链数 > 0（WARN 类） | 归档但写入结项报告的遗留问题 |
| 产出物缺失或哈希不匹配 | 拒绝归档，提示"产出物被外部修改"，由人决定是否重跑上游 |
| 状态文件存在 `in_progress` 步骤 | 拒绝归档，提示先处理该步骤 |

**未实现（P2）。** 依赖 `ai-test-*` 域的产出。当前请按 `templates/批次结项报告模板.md` 人工结项。
