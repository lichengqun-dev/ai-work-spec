# ai-iteration-02-delta-spec · 增量设计

## 能力声明

依据影响面分析产出**增量设计**——只写差异，不重写文档。

**输出的是一份「变更说明」，不是一份新的详细设计。** 这个区别直接决定了 AI 的上下文消耗量级：
重写一份 200 页的详细设计，与描述"某表加一列、某接口加一个参数"，成本差两个数量级。

**不做什么**：不重写原文档、不改原批次产出物、不实现代码、不做影响面分析——见「边界」。

## 何时用 / 何时不用

- **用**：影响面分析已产出，且**影响等级为「中」**时
- **不用**：等级为「小」——走 `ai-daily-01-fastlane`
- **不用**：等级为「大」——转 `02_概要详细设计` 完整流程，**不接受绕过**

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 影响面分析 | `ai-iteration-01-impact` 产出 | 是 | 含受影响 FN / 接口 / 表清单 |
| 原设计文档 | 已归档批次的产出物 | 是 | 基线设计的来源 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | 技术约束 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 增量设计说明 | 项目文档仓 `<需求名>/迭代/<批次号>_增量设计.md` | **差异描述**（改什么 / 为什么 / 影响谁） |
| 建议的变更子批次编号 | 写在增量设计说明内 | 形如 `<原批次号>-C<n>`。**只是建议**——实际的变更子批次由 `ai-iteration-03-change-control` 创建 |

产出结构——**每项差异写清四件事**：

```markdown
### D-01 导出接口新增分组维度筛选

**改什么**：`API-CORE-008` 请求体新增 `groupId`（可选，string，最长 32）
**为什么改**：对应需求 REQ-CORE-031「按分组维度导出」
**原设计是什么**：详见 `<需求名>/02_设计/接口契约.yaml`（原批次 PROJ-20260901-003）
**影响谁**：FN-CORE-045（导出入口）、TC-FN-CORE-045-01~05（需重跑）
```

四件事都要有。缺「原设计是什么」，读者无法判断改动幅度；
缺「影响谁」，回归范围就断了。

## 前置条件

**hard（不满足则拒绝执行）**

- 影响面分析已产出，且**影响等级为「中」**（小 → 走快车道；大 → 转完整流程，**不接受绕过**）
- 原设计文档可定位（找不到基线时拒绝——**没有基线就没有"差异"这个概念**）

**soft（不满足则提示，可继续）**

- 无。影响面分析是硬依赖（它就是差异描述的输入），不存在"没轮到"的情形

## 执行步骤

1. 逐项描述差异，每项写清四件事：
   - **改什么**（精确到字段、参数、页面元素）
   - **为什么改**（对应哪条需求）
   - **原设计是什么**（引用原文档章节号）
   - **影响谁**（受影响 FN / 接口 / 用例）
2. **不重写原文档的任何章节**——只描述差异，原文档保持不可变
3. 建议的变更子批次编号 `<原批次号>-C<n>`
4. 标注哪些差异需要更新契约、哪些需要改表（后者在影响面分析里应为"大"，出现了要停下来重新确认）
5. 回写批次状态文件：本步骤置 `done`，登记增量设计说明与哈希

### 差异描述的粒度

**精确到能被实现的程度**，但不要滑向"重写设计"。
判断标准：**写出来的东西能不能直接用来改代码？** 能，就够细了；如果开始复述没变的部分，就过头了。
正反例与"为什么原文档不可变"的论证见 `references/差异描述要点.md`。

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始
- 本 Skill 没有 soft 前置
- 批次状态文件不可写（如未接入批次）时：产出物落到 `<需求名>/迭代/<批次号>_增量设计.md`，
  跳过状态回写并在报告中说明

## 边界（明确不做）

- **不重写完整设计文档。** 重写会产生两份文档（新的与旧的），而没人知道哪份是当前的
- 不改原批次的产出物（原批次不可变，这是审计链的基础）
- 不实现代码（`03_编码开发`）
- 不做影响面分析（那是上一步）
- **不自行决定"大"级变更怎么处理**——那需要回完整流程
- 不要接受"大"级变更
- 不要把表结构变更写进增量设计
- 不要在影响面分析漏项时顺手补上（回去补范围）
- 不要执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 影响等级为"大" | **拒绝执行**，说明需转完整流程（`02_概要详细设计`） |
| 影响等级为"小" | 拒绝执行，提示走 `ai-daily-01-fastlane` |
| 找不到原设计文档 | 拒绝执行——无基线则差异无从谈起 |
| 增量设计中发现需要改表 | 停止并重新确认影响等级（这一步不该出现表结构变更） |
| 差异描述涉及未在影响面分析中列出的 FN | 停止，回到 `ai-iteration-01-impact` 补全范围 |

## 输出格式

```
变更子批次：PROJ-20260901-003-C1
差异项：3

D-01 导出接口新增分组维度筛选
     API-CORE-008 请求体加 groupId（可选，string，≤32）
     影响：FN-CORE-045、TC-FN-CORE-045-01~05

D-02 列配置默认值调整
     TBL 层无变更；仅前端默认值配置
     影响：FN-CORE-020

D-03 导出结果新增空间列
     响应体新增 groupName 字段
     影响：FN-CORE-046、前端列表渲染

契约需更新：是（API-CORE-008、API-CORE-021）
需改表：否
原批次产出物：未改动（PROJ-20260901-003）
```
