# 知识索引 · ai-iteration-02-delta-spec

> `references/` 默认**只加载本文件**。按下方「何时读取」按需读取，单次不超过 3 个文件、合计 1500 行。
> **本文件内的路径**：`references/` 开头的是本 Skill 内的资源；「知识库根下」开头的是 Skill 之外的资源。

| 知识 | 位置 | 何时读取 |
|---|---|---|
| 差异描述要点（为什么只写差异、粒度正反例） | `references/差异描述要点.md` | 写差异项、拿不准该写多细时 |
| 原批次产出物 | 项目文档仓（基线，**只读**） | **每次必读**——「原设计是什么」从这里取 |
| 影响面分析 | 项目文档仓 `<需求名>/迭代/<批次号>_影响面分析.md` | **每次必读**（范围以它为准） |
| 变更管理规范 | 知识库根下 `05_迭代开发/standards/变更管理规范.md`（`STD-BASE-601`） | 建议变更子批次编号时 |

## 什么时候该在本目录新增文件

- 差异描述的范本（好的与啰嗦的各存一份对比）
- 「哪些改动必须写进增量设计、哪些可以不写」的判据
- 历次增量设计写成了"重写全文"的案例

**最后一类值得记**：写增量设计时最容易滑向"顺手重写一遍"，
而重写的后果是产生两份文档、且没人知道哪份是当前的。
