# 编号挂载与覆盖机制

> 本文件回答「为什么这么定」与「覆盖缺口长什么样」。**编号格式与自查条目本身在 `SKILL.md` 的产出契约与执行步骤里**，本文件不重复规则，只给理由与判据。

## 一、用例编号为什么必须挂载到 FR

`TC-FR-CORE-045-01` 而不是 `TC-001`。

| 挂载形式 | 能回答的问题 |
|---|---|
| `TC-FR-CORE-045-01` | 每个 FR 有多少用例覆盖？哪些 FR 没有用例？回归时该跑哪些？ |
| `TC-001` | 只有"一共有多少条用例" |

**这不是命名偏好**，有两个机制依赖它：

- `fr-has-testcase` 检查项（gate-05 的 BLOCK 级）按 FR 统计覆盖
- `ai-test-04-regression` 圈定回归范围时，走的是 `代码 diff → FR → 用例集合`

**功能覆盖率**（按 FR 统计）与**回归范围圈定**都依赖这条挂载关系。游离编号会让这两个机制同时失效。

## 二、覆盖检查为什么第三条最容易漏

自查的三条里，*详细设计里每条异常分支都有对应用例吗* 是最容易漏的一条。

详细设计写了 5 条异常分支、用例里只覆盖了 2 条——这种产出**在执行率与用例总数上完全看不出来**，
是"覆盖率高但漏测多"的典型形态。前两条（每个 FR 有用例、每个错误码有用例）都有机械可数的对象，
第三条要对着一份散文逐条比对，所以靠的是这一条自查，而不是任何统计数字。
