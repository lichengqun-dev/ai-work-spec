# 判读与误报

> 检查器是**机械判定**的，所以它既会漏报也会误报。这份文件说明它在哪些情况下会误判、
> 以及为什么某些"看起来没问题"的写法确实是问题。

## 一、检查器怎么区分「示例」与「真实引用」

知识库里到处都有**故意写错的编号与 Skill 名**——反例、格式示例、"反面教材"。
如果把它们当成真实引用，每一次检查都会报出一堆噪音，然后没人再看这份清单。
噪音比漏报更快地杀死一个检查器。

所以脚本按「示例标记」判定，命中标记的行**跳过引用检查**：

| 标记 | 判定范围 |
|---|---|
| `示例` `例：` `例如` `参考形态` `占位` `待填` | 全部引用检查 |
| `反例` `反模式` `别扭` `建议` `会得到` | **只**影响 Skill 名引用检查 |

标记按「**该行所属表格的表头**」判定，不是只看本行。因为"示例"常常写在表头
（`| 层级 | 前缀 | 示例 |`），而数据行本身不含这个词。

### 为什么标记词收得这么窄

第一版把「格式」「建议」这类正文常用词也收了进来，结果一行写着
"**格式**不可随意改动"的正文被当成示例，**真实悬空引用反而被跳过**。

所以判读时要记住：**"没报"可能因为它是示例，也可能因为标记词恰好出现在这一行。**
发现该报没报时，先看那一行有没有被误判成示例。

## 二、哪些文件不参与检查

| 范围 | 为什么排除 |
|---|---|
| `.claude/skills/` | **生成的挂载层**。整目录副本（含 `references/`/`scripts/`/`assets/`），由 `ai-spec-mount` 校验与真实定义一致 |
| `projects/` | 项目实例层。项目码、模块码、表名本来就该是项目特有的，不适用共享层的引用规则 |
| `.git/` | 版本库内部 |

> **曾经还排除过一个 `docs/`（提案文档）**——设计文档与演练记录通篇是假设的编号与假想的反例。
> 那个目录已删除：设计理由并入了根 `README.md`，演练记录不再保留。
>
> **副作用要知道**：根 `README.md` 现在**参与引用检查**。
> 在里面写示例时不能再用不存在的编号（比如举反例写 `STD-BASE-999`），
> 那会被当成真实条目引用而报出来。要用示例就挑真实存在的编号，或写成占位形式（`STD-XXX-000`）。

## 三、逐类判读要点

### STD 条目悬空引用

被引用但无定义，**方向可能是错的**：

- 新增条目忘了写 `## STD-XXX-nnn` 标题 → 补定义
- 引用方把编号抄错了 → 改引用

两个方向的处理完全不同。**先确认是哪一个**，不要默认"引用是对的，去补定义"——
那会在知识库里凭空造出一条没人设计过的规范。

### 状态描述与实现矛盾

这一类几乎**总是文档过期**，不是 `status` 写错。

判断方法：看它的 `SKILL.md` 里有没有完整的「执行步骤」与「边界」、有没有被其他 Skill 正常引用。
如果都有，那就是它早已实现、只是文档没跟上。

**复现率最高的一类问题。** 2026-10-20 的审计发现：一次"重写状态节"的修复
只落在一个文件上，同类表述在 12 个文件里原样存活。

### 上下文预算超标

预算写在 `上下文注入规范.md` 里，实际行数在另一个文件里——所以它属于"接缝"。

**不要提高预算上限来消掉告警。** 预算的作用是逼出"哪些内容真的每次都要知道"这个决定；
提高上限等于取消这个决定。

### 挂载层不同步

挂载层的 `description` 过期，后果是**模型按错误的触发条件选 Skill**——
该被调用时不被调用，不该被调用时被调用。它不会报错，只会静默地选错。

**不要手改 `.claude/skills/` 下的文件。** 它是生成物，下次重建就被覆盖。

## 四、当前查不到什么（已知盲区）

报"未发现不一致"时，**必须同时说明这一边界**。把"没查到"说成"没问题"，
比不检查更危险——它让人以为已经验证过了。

| 盲区 | 后果 |
|---|---|
| 跨文件的**数字**一致性 | README 写"37 条"而实际 43 条，查不出来 |
| Markdown **结构合法性** | 畸形标题（`# # 标题`）、表头不一致，查不出来 |
| Skill 是否**空壳** | 文件存在但内容是模板复制，查不出来 |
| 条目正文的**语义**矛盾 | "这条规范与那条规范冲突"，只能靠人 |
| 检查项清单与执行器的**双向**差集 | 只查"门禁引用了未实现的"，不查"实现了但没人用" |

补盲区的方式是**加检查项**，不是加人工核查——人工核查会随时间推移变成走过场。
