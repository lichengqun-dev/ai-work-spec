# ai-requirement-autopilot · 需求段编排

## 能力声明

编排 `00-intake → 01-init → 02-analysis → 03-prototype → 04-prd` 全流程，并在每道门禁处停下等人确认。

**它是编排层，不做事。** 一切实际工作由被编排的 Skill 完成。autopilot 只负责：调用顺序、状态推进、
门禁拦截、失败中止。

## 何时用 / 何时不用

- **用**：用户说「走一遍需求流程」，或要在本域把 00 → 04 按顺序驱动完（含每道门禁停下等人确认）时
- **不用**：只要跑其中一步 → 直接调用那一步的 Skill，不必过编排器；
  路径类型判为 `change` 的批次属于迭代流程 → 转 `ai-iteration-01-impact`，本 Skill 不再往下驱动

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 需求描述 | 用户提供 | 是 | 非空 |
| 项目码 | 用户提供 | 是 | `projects/<项目码>/` 存在 |
| 全部下游 Skill | 各 Skill 目录 | 是 | 每个都有 `SKILL.md` 且前置条件可判定 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 全部下游产出物 | 见各 Skill 的产出契约 | — |
| 完整批次状态 | `projects/<项目码>/.agent/state/<批次号>.yaml` | 各步骤状态与门禁结果齐全 |

## 前置条件

**hard（不满足则拒绝执行）**

- 下游 Skill 全部存在且 `SKILL.md` 可解析
- 当前无同项目的 `in_progress` 批次（**有则必须先续做或关闭，不允许并行两个批次**）
- 需求描述非空，且 `projects/<项目码>/` 存在

**soft（不满足则提示，可继续）**

- 无。本 Skill 是整条链的驱动入口，它之前没有别的阶段或门禁

## 执行步骤

```
00-intake → 01-init → [gate-01] → 02-analysis → 03-prototype → [gate-02] → 04-prd
```

1. 调用 `ai-requirement-00-intake` → 得到批次号与路径类型
2. 依次调用 `01-init` → (gate-01) → `02-analysis` → `03-prototype` → (gate-02) → `04-prd`
3. 每到门禁：调用 `ai-gate-runner`
   - 通过 → 继续
   - 失败 → 停止，输出失败明细与定位，等待人工处理
   - 不确定 → 停下来问，不要猜
4. 全部完成 → 汇总产出物清单，提示进入 `02_概要详细设计`

### 每步的执行规则

**调用前**：读被调用 Skill 的 `SKILL.md`，**逐条核对前置条件**。任一不满足就停下，报告是哪一条不满足——
不要"先跑跑看"。

**调用后**：读它的产出，确认产出物真的存在（不是"它说生成了"）。产出物缺失时停止，不要继续往下走。

### 门禁处

| 结果 | 你的动作 |
|---|---|
| 通过 | 继续下一步 |
| 失败 | **停止**，原样输出失败明细与定位，等待人工处理 |
| 无法自动检查 | 输出人工检查清单，停下等待确认 |

**门禁交给 `ai-gate-runner` 执行**（说"跑 gate-0X"即可），本 Skill 不自己模拟一遍检查。
三种结果的处理：`passed` 继续；`failed` 停止并原样输出失败明细；`pending_manual` 把人工清单
原样转达给用户，等他给出结论与姓名后完成签核。**不要自己判断门禁是否通过。**

### 特殊情况

- **gate-02 未通过**：这是**不可豁免**的门禁，只能回到 03 修正原型重跑。明确告知用户这一点。
- **某步骤产出物已存在**：按该 Skill 的续做分支处理，不覆盖。
- **路径类型是 `change`**：属于迭代流程，**转 `ai-iteration-01-impact`** 做影响面分析，
  由影响等级决定后续走增量设计还是转完整流程。本 Skill 只编排需求段，不要继续往下驱动。

### 失败时的行为

**失败了就停。** 不要：

- 重试一次看会不会好
- 跳过这一步继续
- 自己动手把缺的产出物补上（那会让"哪个 Skill 出了问题"变得不可追溯）

每次失败都要报告：哪一步、什么失败、原样输出失败信息、下一步该做什么。

### 路径类型适配

- `new`：完整执行上述步骤
- `resume`：从状态文件的 `current_step` 恢复，**不重跑 `status: done` 的步骤**；
  但**要校验其产出物哈希**——变了说明有人手工改过，提示用户确认后再决定是否重跑；
  `in_progress` 的步骤从头跑该步骤
- `change`：属于迭代流程，**转 `ai-iteration-01-impact`** 做影响面分析，
  由影响等级决定后续路径

## 独立执行

- **hard 全满足即可单独运行**：本 Skill 本身就是整条链的驱动入口，不必由别的编排器启动
- soft 无；不满足 hard 时拒绝执行并报告是哪一条
- 批次状态文件不可写（如未接入批次）时：停下并说明——编排依赖状态文件推进，
  没有它无法判断该走到哪一步

## 边界（明确不做）

- **不代替门禁做判断。** 门禁说停就停
- 不跳过任何步骤，即使觉得"这一步没必要"
- 不自动续期已过期的豁免
- 不在失败后"重试一下就好了"——失败必须由人处理后重跑
- **不自己动手把缺的产出物补上**
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 任一步骤 Skill 拒绝执行（前置条件不满足） | 停止，报告哪个前置条件不满足 |
| gate-01 / gate-02 未通过 | 停止，输出失败明细；**不尝试绕过** |
| gate-02 未通过 | 特别注意：这是不可豁免的门禁，只能回到 03 修正原型 |
| 门禁返回 `pending_manual` | 原样转达人工清单，等用户给出结论与姓名后完成签核 |
| 某步骤产出物已存在 | 按对应 Skill 的续做分支处理，不覆盖 |
| 调用后产出物缺失 | 停止，不要继续往下走 |

## 输出格式

执行中用下面结构回报（每次停下都要给一次）：

```
批次：PROJ-20261019-001（new）
当前步骤：02-analysis

✅ 00-intake  完成  批次号 PROJ-20261019-001
✅ 01-init    完成  文档仓 + 原型仓已初始化
⏸  gate-01    等待人工确认
   → 请核对 07_质量门禁/gates/gate-01-需求准入.md 的检查项
   → 确认后回复"通过"或"不通过"+原因

（通过后将继续 02-analysis → 03-prototype → gate-02 → 04-prd）
```

## 与其他 Skill 的关系

- 编排（按序调用）：`ai-requirement-00-intake` → `01-init` → `02-analysis` → `03-prototype` → `04-prd`
- 门禁：`ai-gate-runner` 执行 gate-01 / gate-02，本 Skill 只转达结果
- 转出：路径类型为 `change` 时转 `ai-iteration-01-impact`；全部完成进入 `02_概要详细设计`
- 上层：`ai-flow-autopilot`（总入口，判定该走哪条路径）
