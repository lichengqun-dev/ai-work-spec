# 知识索引 · ai-spec-mount

**本 Skill 目前没有独立的知识文件。**

它执行时需要的规范放在**域级** `00_工作空间配置/`：

> **本文件内的路径**：`references/` 开头的是本 Skill 内的资源；「知识库根下」开头的是 Skill 之外的资源。
> 下表的两个文件属于后者——挂载层本身不含它们，写相对 skill 目录的路径在挂载位置会直接断。

| 文件 | 何时读取 |
|---|---|
| **知识库根下** `00_工作空间配置/Skill 编写规范.md` | 需要判断某个 Skill 的 frontmatter 是否合规、`description` 该怎么写时 |
| **知识库根下** `00_工作空间配置/命名与编号规范.md` | 挂载层出现孤儿（知识库里已无此 Skill）时，判断它是被删了还是被改名了 |

## 为什么 `description` 单独值得一说

挂载层里只保留两个字段：`name` 与 `description`。其中 **`description` 决定一切**——
它是 Claude 判断"什么时候该用哪个 skill"的唯一依据。

所以它的写法要求与普通文档摘要不同：

| 写法 | 效果 |
|---|---|
| "本 Skill 重建挂载层" | ❌ 只说了**做什么**，模型无从判断何时该用 |
| "新增、重命名、删除 Skill 或改了它们的 description 之后使用" | ✅ 说了**何时触发** |

判据一句话：**写"什么时候该用它"，不写"它是干什么的"。**

## 什么时候该在本目录新增文件

当出现**只有这个 Skill 用得上**的知识时。例如：

- 已确认的挂载层故障案例（"某次 description 写错导致调用了错误的 Skill"）
- 挂载层与真实定义分叉的具体形态

**判据**：同域其他 Skill 会不会用到？会 → 放域级。
共用知识在每个 Skill 下各存一份，是知识库腐化的典型起点——改一处忘另一处。
