# ai-archive-01-close · 批次结项与归档

## 能力声明

**批次结项**：归集产出物、执行断链检测、回填索引、生成结项报告，并把批次状态文件终态化。

**它同时是 gate-06 的产出方。** 此前 gate-06 检查的几项（状态终态化、产出物齐备、结项报告）
在流程里没有负责人——本 Skill 补上这一环。

本 Skill 只做**归集与核对**：检查项判断交给 `ai-gate-runner`，断链的补全交给人。

**不做什么**：不修改产出物内容、不补链、不手工改产出物来满足哈希校验、不执行 git 操作——见「边界」。

## 何时用 / 何时不用

- **用**：批次走到收尾，要跑 gate-06 并按结果归档时
- **不用**：补文档 / 补用例让断链归零（那是人的工作）；改产出物使其符合校验（任何阶段都不该做）
- **断链非 0 时仍走本 Skill**，但按 BLOCK / WARN 分级处理（见「执行步骤」）

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 批次状态文件 | `projects/<项目码>/.agent/state/<批次号>.yaml` | 是 | 各 steps 已终态；gate-05 已 passed/waived |
| 功能编号总表 | `projects/<项目码>/.agent/index/功能编号总表.md` | 是 | 含本批次的 REQ / FN / TC |
| 全部产出物 | 项目文档仓 `docs/` | 是 | 已登记在状态文件的 `artifacts` |
| 测试报告 | `ai-test-05-report` 产出 | 是 | 含上线建议 |
| 上线步骤 | `ai-iteration-04-release` 产出 | 是（gate-06 前置） | 含回滚方案 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 结项报告 | 项目文档仓 `<需求名>/05_交付/结项报告.md` | 按知识库根下 `08_归档交付/templates/批次结项报告模板.md` |
| 断链检测结果 | 结项报告「三、断链检测」节 + `projects/<项目码>/.agent/index/功能编号总表.md` 断链视图 | 五类断链的计数与明细 |
| 索引回填 | `projects/<项目码>/.agent/index/功能编号总表.md` | 功能点段的「批次」「提交」「覆盖用例」列 |
| 终态化状态文件 | `projects/<项目码>/.agent/state/<批次号>.yaml` | `archived: true` + 归档时间 |

产出结构——结项报告里最要紧的一节：

```markdown
## 六、遗留问题与技术债

| # | 问题 | 影响 | 处置计划 | 负责人 |
|---|---|---|---|---|
| 1 | 3 条用例因第三方沙箱不可用未执行 | FN-CORE-047 的对接受阻未验证 | 沙箱恢复后 24 小时内补测 | 张三 |
| 2 | FN-CORE-046 无提交关联（项目仓未接 git） | 无法回答该功能由哪次提交上线 | 接入 git 后重跑 gate-06 | 李四 |
```

**不要把遗留问题写得含糊。** "部分功能待完善"没有任何信息量；
"3 条用例未执行、涉及 FN-CORE-047、原因是沙箱不可用"才能被处置。

总表三列填什么：

| 列 | 填什么 | 来源 |
|---|---|---|
| 覆盖用例 | `TC-FN-XXX-000-NN` | 测试用例文件 |
| 提交 | commit hash 或 PR 号 | 代码仓 git log（按 FN 编号反查） |
| 批次 | 本批次号 | 当前批次 |

**只填真实值。** 查不到的留空并在结项报告的遗留问题里写明——**不要填"待补"这种占位**，
它会让人以为之后有人会补。

## 前置条件

**hard（不满足则拒绝执行）**

- 批次状态文件存在，且各步骤为终态（`done` / `skipped` / `failed`），无 `in_progress`
  ——gate-06 的 `state-steps-final` 要求 `steps` 全部终态**且 `current_step` 在 `steps` 中**（精确匹配其一）
- 状态文件记录了 `spec_snapshot.hash`（回答"这个批次用的是哪版规范"）
- 功能编号总表已回填、含本批次的 REQ / FN / TC
- 产出物已登记在状态文件的 `artifacts`，且文件存在、哈希一致
- `ai-gate-runner` 已实现（gate-06 的检查项由它执行）

**soft（不满足则提示，可继续）**

- gate-05 状态为 `passed` 或 `waived`（未满足时产出物标注「未经上游确认 —— gate-05 未通过」，
  状态记 `partial`，**不得把状态文件置为 `archived: true`**）

## 执行步骤

1. **先跑 gate-06**（调用 `ai-gate-runner`，说"跑 gate-06"即可），**不手工判断**。
   自动检查项交给执行器；人工项原样列出，**不代替人判断**。结果为 `failed` 就停下。
2. **执行断链检测**（五类，见知识库根下 `00_工作空间配置/命名与编号规范.md` 第 9 节）：

   | 类型 | 判据 | 级别 |
   |---|---|---|
   | 无 REQ 来源的 FN | 总表「来源 REQ」列空 | **BLOCK** |
   | 无设计章节的 FN | 该 FN 未出现在设计类产出物中 | **BLOCK** |
   | 无测试用例覆盖的 FN | 该 FN 没有挂载的 `TC` | **BLOCK** |
   | 无对应提交的 FN | 该 FN 未出现在任何提交信息中 | WARN |
   | 孤儿编号 | 总表有登记但无任何产出物引用 | WARN |

   **BLOCK 类非 0 → 拒绝归档。WARN 类非 0 → 归档，但写进结项报告的「遗留问题」节。**
   分级的理由：前两类是"东西缺了"，后两类是"没能证明它在"。
   后者可能是环境问题（没接 git、产出物命名不同），前者不是。

   **不要在门禁通过后跳过断链检测**——门禁的 `fn-has-commit` 在项目仓不是 git 仓库时只能记 `skip`，
   那时断链数在门禁视图里显示为 0，而实际上只是"没查"。

   **断链了不要"顺手补上"。** 补链意味着补文档或补用例——**那是人的工作**。
   脚本能做的只是把断链指出来并定位到具体对象：

   ```
   ❌ FN-CORE-047 没有挂载用例
      定位：功能详细设计 §FN-CORE-047 存在，但测试用例文件中无 TC-FN-CORE-047-*
      → 需补充用例，或确认该 FN 是否应被拆掉
   ```

3. **回填总表**：「覆盖用例」「提交」「批次」三列。这三列此前由谁填没有定义——本 Skill 负责。
4. 生成结项报告：批次概览、交付内容、断链结果、门禁记录、豁免记录、遗留问题、本批次产生的规则。
5. 把状态文件置 `archived: true` 并记录归档时间。
   **归档后状态文件只读**——此后任何修改请求都应被拒绝；**已归档的状态文件不得删除**，追溯链依赖它。
6. 提示运行 `ai-spec-promote` 分析本批次产生的项目特有条目
   （同一条约束出现在 ≥3 个项目 → 建议提升为共享包条目）。

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始
- soft 不满足时照常产出结项报告，并在产出物顶部标注「未经上游确认 —— gate-05 未通过」，
  状态记 `partial`，**不置 `archived: true`**
- 批次状态文件不可写（如未接入批次）时：产出物落到指定路径，跳过状态回写并在报告中说明

## 边界（明确不做）

- **不修改产出物内容**，只核对存在性与哈希
- **不补链**。断链意味着缺文档或缺用例，那是人的工作——脚本只能把断链指出来并定位
- **不删除任何文件（含 `projects/<项目码>/.agent/state/` 下已归档的状态文件——追溯链依赖它）**
- 不改状态文件里已有的 `steps` / `current_step` / `artifacts` 记录（只做终态化与登记）
- **不在断链非 0 时静默归档**（BLOCK 类非 0 直接拒绝）
- **不要在门禁 `failed` 时继续**
- 不要手工改产出物来满足哈希校验
- **不要在总表里填"待补"这类占位**——查不到的留空并在遗留问题里写明
- 不要执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| gate-06 `failed` | 停止，输出未通过项与定位；**不尝试绕过** |
| 断链数 > 0（BLOCK 类：无 REQ 来源 / 无设计章节 / 无用例覆盖） | **拒绝归档**，列出断链明细与定位；**不补链**来让它归零 |
| 断链数 > 0（WARN 类：无提交 / 孤儿编号） | 归档，但写入结项报告的「遗留问题」节 |
| 产出物缺失或哈希不一致 | 拒绝归档，提示"产出物被外部修改"，由人决定是否重跑上游 |
| 状态文件有 `in_progress` 步骤，或 `current_step` 不在 `steps` 中 | 拒绝归档，提示先处理该步骤——gate-06 的 `state-steps-final` 要求 `current_step` **精确匹配 `steps` 中的某一项** |
| 项目仓不是 git 仓库 | 提交类断链无法判定——**明确记为「未校验」而不是 0**（这一点执行器也会说） |
| 被要求删除已归档的状态文件 | **拒绝执行**。已归档的状态文件**不得删除**——追溯链依赖它，这是全局红线之一 |
| 被要求在归档后修改状态文件 | **拒绝执行**。归档后状态文件只读，任何修改请求都应被拒绝 |
