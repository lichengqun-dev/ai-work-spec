# 知识索引 · ai-iteration-03-change-control

> `references/` 默认**只加载本文件**。按下方「何时读取」按需读取，单次不超过 3 个文件、合计 1500 行。
> **本文件内的路径**：`references/` 开头的是本 Skill 内的资源；「知识库根下」开头的是 Skill 之外的资源。

| 知识 | 位置 | 何时读取 |
|---|---|---|
| 变更登记要点（为什么原批次不可变、哈希与批准的口径） | `references/变更登记要点.md` | 登记基线、写"待批准"、判断"什么叫已批准"时 |
| **变更管理规范** | 知识库根下 `05_迭代开发/standards/变更管理规范.md`（`STD-BASE-601`） | **必读** |
| 批次状态模板 | 知识库根下 `projects/_template/.agent/state/_模板.yaml`（`type: change` 与 `parent_batch` 字段） | 生成子批次状态文件时 |
| 原批次状态文件 | 知识库根下 `projects/<项目码>/.agent/state/<原批次号>.yaml` | 每次必读——先确认 `archived: true` |

## 什么时候该在本目录新增文件

- 变更登记的范本
- 「什么算已批准」的判据（群里说一句算不算？）
- 历次"原批次被改动"的案例（如果发生过）

**最后一类如果真的发生了，值得当成事故复盘**——它意味着审计链的地基被破坏了。
