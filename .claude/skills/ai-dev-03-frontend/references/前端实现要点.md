# 前端实现要点

> 本文件承载**「为什么」**：迁移与重画的分界、状态归属的判据、异常态为什么必须统一。
> 「做什么」在 `SKILL.md` 的执行步骤与边界里，不重复。

## 一、迁移，不要重画

原型是**业务方已经确认过的形态**。你的工作是把它落成工程实现，不是重新设计一遍界面。

**从原型迁移时保留布局骨架与交互模式。** 迁移动机是"让它工程化"，不是"让它更好看"。

重画会带来一个隐蔽的代价：业务方确认过的那一版从此不存在了，
而中间发生的差异不会有人再回头核对。

## 二、组件复用是第二次机会

`ai-requirement-03-prototype` 阶段已经做过一次"先匹配已有组件"，这里是第二次——
那次是概念层面，这次要落到具体组件。

**新组件要写明拆出的理由**，否则很容易出现"同一个表格在五个页面各写了一遍，
每一遍处理方式都稍有不同"。

## 三、状态归属：最容易出错的地方

前端设计里已经标注了每个状态的归属，照着做。判据回顾：

| 状态类型 | 归属 | 为什么 |
|---|---|---|
| 接口返回的数据 | 请求层（hook / service） | 它是服务端状态，有"一份还是多份"的问题 |
| 跨页面共享的 UI 状态 | 全局 store | 多个页面读同一份 |
| 单页面 UI 开关、tab、表单草稿 | 组件本地 | 离开页面就该丢 |

**不要顺手把接口数据放进全局 store。** 放进去了之后，缓存失效、竞态、重复请求全要手工处理，
而且容易出现"两个页面看到同一份过期数据"——这类问题在测试阶段极难复现。

## 四、异常态与空态必须实现

前端设计里列了每个页面的三种态，照着做：

| 态 | 常见做法 |
|---|---|
| 无数据 | 空状态提示 vs 空表格（按设计定） |
| 无权限 | 隐藏入口 vs 显示 403（按设计定） |
| 加载失败 | 重试按钮 + 错误提示 |

**不要三个页面三种做法。** 异常态在实现阶段随手写的结果，通常是每个页面各写一套。
