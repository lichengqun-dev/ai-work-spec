# ai-work-spec

AI 原生化研发知识库。覆盖 需求 → 设计 → 开发 → 测试 → 归档 全流程，供多个项目复用。

## 新人上手三步

1. 读根目录 `CLAUDE.md` —— 技术栈基线、全局禁止、Skill 路由。
2. 找到你负责的项目：`projects/<项目码>/project.yaml` —— 它用了哪些规范包、有哪些项目特有差异。
3. 读生效快照 `.ai/spec-effective/<项目码>.md` —— **这是你实际要遵守的规范全文**。不要逐个去读包文件。

如果快照不存在，先执行 `ai-spec-build --project <项目码>` 生成。

## 两个特殊目录

- `projects/` —— **项目实例层**。每个项目一个目录，里面只有 `project.yaml`（声明用了哪些规范包 + 有哪些差异）和项目特有条目。**不含任何共享规范的正文。**
- `.ai/` —— **机器状态区**。批次状态机、功能编号总表、生效规范快照。人少看，AI 高频读写。

## 交付路线图

| 阶段 | 内容 | 周期 |
|---|---|---|
| **P0** | 地基 + 需求流水线：目录、00 配置、规范包骨架、项目 manifest、`ai-spec-build`、需求域 Skill、六道门禁定义 | 4 周 |
| **P1** | 设计 + 开发流水线：`02` `03` 两域 Skill、契约冻结、代码评审 | 5 周 |
| **P2** | 测试 + 迭代 + 日常：`04` `05` `06` 三域 Skill | 4 周 |
| **P3** | 资产沉淀与度量：领域模型、组件库、故障案例库、度量指标 | 持续 |

**各阶段必须串行。** P1 的契约冻结依赖 P0 的编号体系；P2 的影响面分析依赖 P1 产出的依赖关系图。并行推进必然返工。

## 这是一个通用资产

本仓库 `00`–`09` 与 `.ai/` 都是**项目无关的**：只有机制、规范模板与通用工程约束，
不出现任何具体项目的名称、模块、表名或业务规则。

**具体项目的一切只存在于 `projects/<项目码>/` 下。** 边界规则见 [`projects/README.md`](./projects/README.md)。

套用到其他团队时：保留 `00`–`09`、`.ai/`、`projects/_template/`，
清空 `projects/` 下的其他目录，按自己的技术栈增删规范包即可。

新增项目：复制 `projects/_template/`，填 `project.yaml`，执行 `ai-spec-build`。目标耗时 ≤ 30 分钟。
