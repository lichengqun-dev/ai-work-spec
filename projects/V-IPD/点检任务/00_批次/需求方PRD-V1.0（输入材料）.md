## 1. 背景与目标

### 1.1 背景

当前 V-IPD 中的任务（交付物任务、空类型任务等）创建后缺少过程跟踪机制，任务负责人无法被定期提醒更新进展，项目经理也难以及时掌握任务真实进度。现有「修改点检时间」能力只是一个孤立的时间字段维护入口，没有形成闭环。

### 1.2 目标

1. 为任务提供**周期性的点检机制**：按可配置间隔自动生成点检任务，推动责任人定期更新进度。
2. 支持点检人**手动发起**点检任务，覆盖临时点检场景。
3. 点检任务的反馈结果（进度、进度说明）**回写到原始任务**，形成「点检 → 反馈 → 回写 → 关闭」的闭环。
4. 在原始任务上新增「点检任务」页签，集中展示所有关联点检任务，便于追溯。

### 1.3 成功标准

- 原始任务未完成时能按配置周期持续生成点检任务，完成后自动停止。
- 点检任务反馈后，原始任务实际进度与反馈信息实时更新，且历史反馈记录不被覆盖。
- 点检任务进度填 100% 时，触发原始任务的关闭逻辑。

## 2. 术语定义

| 术语 | 说明 |
|-|-|
| 原始任务 | 被点检的任务，如交付物任务、业务任务等（点检任务以外的所有任务类型） |
| 点检任务 | 由原始任务派生、用于周期性跟踪进度的新任务，任务类型固定为「点检任务」 |
| 点检人 | 原始任务上配置的点检负责人，是手动生成按钮的权限主体，也是点检任务的创建人 |
| 生成间隔 | 两次点检任务之间的间隔天数，可配置（标准周期 14 天，示例值 7 天 / 12 天） |
| 完成偏移 | 点检任务「计划完成时间 = 计划开始时间 + N 天」中的 N，可配置（示例值 3 天） |
| 回写 | 将点检任务反馈的进度与进度说明写入原始任务的实际进度与反馈信息 |

## 4. 功能需求详述

### 4.1 F-01 点检任务自动生成

#### 4.1.1 触发条件

- 原始任务**未完成**时，按配置的生成间隔**持续生成**点检任务（不是只生成一次）。
- 原始任务**已完成**时，停止生成。
- 生成时机示意（间隔 = 7 天，原始任务计划开始 10-01）：

  | 轮次 | 触发日期 | 说明 |
  |-|-|-|
  | 第 1 轮 | 10-08 | 计划开始 + 7 天 |
  | 第 2 轮 | 10-15 | 计划开始 + 14 天 |
  | 第 3 轮 | 10-22 | 计划开始 + 21 天 |
  | …… | …… | 直到原始任务完成 |

#### 4.1.2 短周期任务的边界（需确认口径）

- 若原始任务的时间跨度 ≤ 生成间隔（示例：1 号开始、8 号结束，间隔 7 天），**不生成**点检任务 —— 任务本身到期即结束，无需点检。
- 只有跨度大于间隔（示例：1 号开始、9 号结束）才需要生成。
- 口径建议：`(计划完成时间 − 计划开始时间) > 生成间隔` 才触发生成，且已生成的点检任务计划开始时间不得晚于原始任务计划完成时间。最终阈值由需求方与开发确认后固化。

#### 4.1.3 时间计算规则

| 字段 | 规则 |
|-|-|
| 点检任务·计划开始时间 | 原始任务计划开始时间 + 生成间隔（可配置，单位：天） |
| 点检任务·计划完成时间 | 点检任务计划开始时间 + 完成偏移（可配置，单位：天） |
| 点检任务·实际开始/完成时间 | 生成时为空，由责任人在反馈时填写 |

- 示例（间隔 12 天、偏移 3 天，原始任务计划开始 10-01）：点检任务计划开始 = 10-13，计划完成 = 10-16。
- 两个配置项（生成间隔、完成偏移）为**系统/项目级配置**，不在任务上新增节点时间字段。

#### 4.1.4 字段继承规则

| 点检任务字段 | 取值规则 |
|-|-|
| 任务类型 | 固定「点检任务」 |
| 责任人 | 继承原始任务的责任人 |
| 关联阶段 | 继承原始任务的关联阶段 |
| 项目角色 | 继承原始任务的项目角色 |
| 任务类别 | 继承原始任务的任务类别（点检场景固定归类为点检任务） |
| **创建人** | **取原始任务的点检人**（不写「系统」） |
| 关联项目 / 项目 | 继承原始任务 |
| 路径信息 | 继承原始任务的项目 / 计划 / 阶段路径 |
| 进度 | 默认带出原始任务当前进度，供责任人修改 |
| 点检时间 / 点检人字段 | **不继承、不展示**（见 4.6 字段精简） |

> 说明：Demo 原型中点检任务的创建人写的是「系统」，与会议结论不一致，**实现时以本条为准**：创建人 = 原始任务的点检人。

### 4.2 F-02 点检任务手动生成

| 规则项 | 说明 |
|-|-|
| 入口 | 原始任务详情页右上角按钮「生成点检任务」 |
| 权限 | **仅原始任务的点检人可见并可点击**；其他用户隐藏该按钮（不做点击后校验，直接隐藏）。多个点检人时，均可执行 |
| 时间填写 | 手动生成时，点检任务的计划开始 / 完成时间由用户自行填写（不走自动计算逻辑） |
| 时间校验 | 填写的时间**不得早于当前日期**（今天 7 号，填 6 号不合法；≥ 今天） |
| 其他字段 | 与自动生成一致（继承责任人、关联阶段、角色、类别、路径；创建人取点检人） |
| 生成限制 | 不限制次数；已存在未完成的点检任务时仍允许再次生成（由点检人自行判断） |
| 生成结果 | 生成一条新的点检任务，并挂载到原始任务的「点检任务」页签下 |

### 4.3 F-03 点检任务反馈

点检任务责任人通过「任务反馈」提交进展，反馈表单字段：

| 字段 | 是否必填 | 校验规则 |
|-|-|-|
| 实际开始时间 | 必填 | 日期；未填写时不允许保存 |
| 实际完成时间 | 选填 | 日期 |
| 进度 | 必填 | **整数，取值 1\~100**；不做「不得小于上次进度」「多次进度之和」等逻辑约束 |
| 是否有风险 | 选填 | 是 / 否 |
| 进度说明 | 必填 | 文本；未填写时不允许保存 |

- 进度默认值：带出该点检任务所属原始任务的当前进度，责任人在此基础上修改。
- 进度**可以回退**（例如上次 30%、本次改 20%），系统不做拦截，由责任人自行负责。
- 反馈入口：

  - 工作台任务列表点击点检任务 → 直接打开反馈弹窗；
  - 点检任务详情页右上角「任务反馈」按钮。
- 反馈保存后，该点检任务置为「已完成」。

### 4.4 F-04 数据回写规则

| 规则项 | 说明 |
|-|-|
| 回写字段 | 进度 → 原始任务实际进度；进度说明 → 原始任务反馈信息；实际开始 / 完成时间同步回写 |
| 回写方式 | 每次反馈在原始任务反馈信息中**新增一条记录**，**不覆盖**已有记录 |
| 双向并存 | 原始任务自身的「任务反馈」入口保持原样不动；通过原始任务反馈与通过点检任务反馈，都会各生成一条记录，共同展示在反馈列表中 |
| 实时性 | 回写后原始任务「基本信息」页的实际进度、进度说明、反馈信息实时更新 |
| 记录内容 | 每条记录包含：反馈人（点检任务取责任人 / 点检人）、反馈时间、进度、进度说明 |

### 4.5 F-05 原始任务「点检任务」页签

- 在原始任务详情页的页签中**新增「点检任务」页签**（位于「关联任务」之后）。
- 页签内以列表形式展示该原始任务关联的全部点检任务：

  | 列 | 说明 |
  |-|-|
  | 标题 | 点检任务标题，可点击进入点检任务详情 |
  | 状态 | 正常 / 预警 / 超期 / 已完成（沿用现有状态样式） |
  | 计划开始 | 点检任务计划开始时间 |
  | 计划完成 | 点检任务计划完成时间 |
  | 实际开始 | 反馈填写的实际开始时间，未填显示「-」 |
  | 实际完成 | 反馈填写的实际完成时间，未填显示「-」 |
- 无关联点检任务时展示空态「暂无点检任务」。
- 自动生成与手动生成的点检任务**统一挂载**在该页签下。

### 4.6 F-06 进度 100% 自动关闭

- 点检任务反馈进度 = 100% 时，进度回写到原始任务，原始任务实际进度变为 100%，**触发原始任务的关闭逻辑**（与任务正常完成时的关闭逻辑一致）。
- 关闭后，原始任务状态置为已完成，后续不再生成点检任务。

### 4.7 F-07 任务类型与适用范围

- 新增任务类型「点检任务」，在工作台任务列表以独立标签展示，支持按类型筛选。
- **适用范围**：除点检任务自身外，其余所有任务类型（交付物任务、业务任务、空类型任务等）均支持生成点检任务。
- **排除**：点检任务不可再生成点检任务，其详情页不展示「生成点检任务」按钮。

### 4.8 F-08 按钮替换与 F-09 字段精简

| 现状 | 调整后 |
|-|-|
| 原始任务详情页「修改点检时间」按钮 | **下线**，替换为「生成点检任务」按钮（权限见 4.2） |
| 任务详情信息栏「点检时间」「点检人」字段 | **去掉**，不再展示 |
| 点检任务详情页冗余字段 / 评论输入区 | **精简移除**（原型中已删除评论输入框） |
| 原始任务现有页面逻辑与其他页签 | **保持不变**，不做改造 |

### 4.9 F-10 点检任务详情页与层级样式

- 点检任务详情页展示继承的路径信息：`项目 / 交付物计划 / 阶段 / 原始任务名称`，与原始任务详情页的路径格式保持一致。
- 点检任务的层级、路径样式沿用系统现有通用交互逻辑（不使用平铺展开效果），保持与现有任务一致的视觉与交互。
- 点检任务详情页提供「返回」入口，可回到原始任务。

## 6. 页面与交互规范

1. **改造范围**：保留原始任务现有页面逻辑不动，仅新增「点检任务」页签；页签内容采用**硬编码开发**（在现有低码配置表单基础上新增写死的页签），不改造低码配置部分。
2. **样式一致性**：按钮、标签、状态点、表格、弹窗等沿用 V-IPD 现有组件与样式；点检任务层级与路径样式与系统现有通用交互保持一致。
3. **反馈弹窗**：点检任务的反馈弹窗顶部展示来源原始任务的信息块（责任人、状态、关联阶段、项目角色、任务类别、创建人、计划开始 / 完成）与路径面包屑，路径末尾显示**原始任务标题**（而非点检任务自身标题）；下方为反馈表单与历史反馈记录。
4. **精简原则**：移除与点检无关的冗余字段与区域（如评论输入区），输出精简、真实、精确的原型给开发。

## 7. 非功能性要求

| 类型 | 要求 |
|-|-|
| 环境 | dev 环境不稳定，**开发联调直接使用测试环境（UAT）**；需提前为开发人员开通 UAT 访问权限、账号及数据库连接权限 |

| 数据一致性 | 点检任务与原始任务的关联关系必须落库，保证页签挂载与回写链路可靠 |
| 兼容性 | 不影响现有任务反馈、任务列表、任务详情等既有功能 |

## 8. 异常与边界场景

| 场景 | 处理建议 |
|-|-|
| 原始任务在两次点检之间完成 | 已完成状态的任务不再生成新的点检任务 |
| 同一原始任务已存在未完成的点检任务 | 到周期仍继续生成；手动生成也不限制次数 |
| 手动生成时点检人有多人 | 每位点检人均可见按钮并可生成 |
| 点检任务反馈进度为 100% 后又再次反馈 | 以回写规则为准，新增记录；原始任务已关闭则不再触发 |
| 原始任务计划时间变更 | 已生成的点检任务时间不追溯修改；新周期按变更后的计划开始时间计算（口径待确认） |
| 定时任务执行失败 | 记录日志并支持补偿生成，避免漏发 |

## 9. 验收标准（要点）

1. 原始任务未完成且跨度大于间隔时，按配置周期依次生成点检任务；任务完成后不再生成。
2. 自动生成的点检任务字段继承正确，创建人 = 原始任务点检人，计划开始 = 原始任务计划开始 + 间隔，计划完成 = 计划开始 + 偏移。
3. 非点检人看不到「生成点检任务」按钮；点检人可见并可手动生成，时间早于今天时被拦截。
4. 进度只能填 1\~100 整数，可回退修改，不产生额外约束报错。
5. 反馈保存后：点检任务置为已完成；原始任务实际进度、进度说明更新；反馈信息新增一条记录且历史记录保留。
6. 原始任务「点检任务」页签展示全部关联点检任务，点击可进入详情并返回。
7. 点检任务反馈 100% 时，触发原始任务关闭。
8. 点检任务不可再生成点检任务；其他类型任务均可生成。
9. 页面样式与现有系统一致，点检任务详情页展示继承的路径信息。
