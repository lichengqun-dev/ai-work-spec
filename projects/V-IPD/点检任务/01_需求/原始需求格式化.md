## REQ-TASK-001 · 点检任务自动生成（周期性跟踪）

| 要素 | 内容 |
|---|---|
| **角色** | 项目计划管理员（配置方）；任务责任人（受限方）|
| **场景** | 原始任务已下发且**尚未完成**，需要定期推动责任人更新进展，而人工催办靠不住 |
| **行为** | 系统按可配置的**生成间隔**周期性扫描未完成的原始任务，到期即生成一条点检任务 |
| **结果** | 责任人持续收到点检任务；原始任务的真实进度被周期性刷新；任务完成后自动停止生成 |
| **验收** | 间隔 7 天、原始任务计划开始 10-01 → 10-08 / 10-15 / 10-22 各生成一条；原始任务完成后不再产生新的点检任务 |

**边界（本期不做）**：不推送消息通知（PRD 未要求）；不对已完成任务补生成。

## REQ-TASK-002 · 点检人手动发起点检

| 要素 | 内容 |
|---|---|
| **角色** | 原始任务的**点检人**（权限主体） |
| **场景** | 临时需要催办或跟踪，等不到下一个自动周期 |
| **行为** | 在原始任务详情页点「生成点检任务」，**自行填写**计划开始 / 完成时间（不走自动计算） |
| **结果** | 新增一条点检任务并挂载到原始任务下；生成次数不限 |
| **验收** | 非点检人**看不到**该按钮（直接隐藏，非点击后报错）；填写时间早于今天被拦截；已有未完成点检任务时仍可再生成 |

## REQ-TASK-003 · 点检任务反馈

| 要素 | 内容 |
|---|---|
| **角色** | 点检任务责任人 |
| **场景** | 收到点检任务后填报当前进展 |
| **行为** | 填写实际开始时间、实际完成时间、进度、是否有风险、进度说明并保存 |
| **结果** | 该点检任务置为「已完成」；反馈内容进入回写链路（见 REQ-TASK-004） |
| **验收** | 实际开始时间与进度说明必填，缺任一项不允许保存；进度为 **1\~100 整数**；进度**可回退**（30% → 20% 不报错）；两个入口都能打开反馈（工作台列表点击、详情页按钮） |

**边界（本期不做）**：不做「不得小于上次进度」这类单调性约束；不做多次进度累计。

---

## REQ-TASK-004 · 反馈回写原始任务（新增记录、不覆盖）

| 要素 | 内容 |
|---|---|
| **角色** | 原始任务的相关人（回写的受益方） |
| **场景** | 点检任务反馈后，原始任务需要反映最新进展，同时保留历史 |
| **行为** | 把点检任务的进度、进度说明、实际开始/完成时间回写到原始任务 |
| **结果** | 原始任务「基本信息」页的实际进度、进度说明、反馈信息**实时更新**；反馈信息以**新增一条记录**的方式追加 |
| **验收** | 历史反馈记录**不被覆盖**；原始任务自身的「任务反馈」入口保持原样，两个入口各生成一条记录，**共同展示**在反馈列表中 |

## REQ-TASK-005 · 原始任务「点检任务」页签

| 要素 | 内容 |
|---|---|
| **角色** | 项目经理、原始任务相关人 |
| **场景** | 查看某个原始任务的全部点检历史，判断进展是否正常 |
| **行为** | 切到原始任务详情页的「点检任务」页签 |
| **结果** | 列表展示该原始任务关联的**全部**点检任务（自动生成与手动生成统一挂载） |
| **验收** | 页签位于「关联任务」之后；列为 标题 / 状态 / 计划开始 / 计划完成 / 实际开始 / 实际完成，未填显示「-」；无关联时显示空态「暂无点检任务」；点标题可进入点检任务详情 |

## REQ-TASK-006 · 进度 100% 触发原始任务关闭

| 要素 | 内容 |
|---|---|
| **角色** | 点检任务责任人（触发方） |
| **场景** | 点检反馈时把进度填到 100%，表示工作已完成 |
| **行为** | 系统把 100% 回写原始任务，并触发原始任务的**关闭逻辑** |
| **结果** | 原始任务状态置为已完成；后续不再生成点检任务 |
| **验收** | 关闭逻辑与任务正常完成时**一致**；关闭后再有反馈不再触发关闭（幂等） |

## REQ-TASK-007 · 新增任务类型「点检任务」

| 要素 | 内容 |
|---|---|
| **角色** | 所有任务使用者 |
| **场景** | 在工作台任务列表中识别并区分点检任务 |
| **行为** | 注册任务类型「点检任务」，列表以独立标签展示，支持按类型筛选 |
| **结果** | 点检任务可被识别、筛选；且有明确的适用范围 |
| **验收** | **除点检任务自身外**，其余所有任务类型（交付物任务、业务任务、空类型任务等）均可生成点检任务；点检任务详情页**不展示**「生成点检任务」按钮 |

## REQ-TASK-008 · 按钮替换：修改点检时间 → 生成点检任务

| 要素 | 内容 |
|---|---|
| **角色** | 原始任务使用者 |
| **场景** | 原「修改点检时间」只是一个孤立的时间字段维护入口，未形成闭环 |
| **行为** | **下线**「修改点检时间」按钮，替换为「生成点检任务」 |
| **结果** | 同一位置从"维护一个字段"变为"发起一次点检" |
| **验收** | 原按钮不再出现；新按钮的可见性规则见 REQ-TASK-002 |

## REQ-TASK-009 · 字段精简

| 要素 | 内容 |
|---|---|
| **角色** | 原始任务 / 点检任务的使用者 |
| **场景** | 页面上存在与点检无关的冗余字段与区域 |
| **行为** | 移除原始任务详情信息栏的「点检时间」「点检人」展示；移除点检任务详情页的冗余字段与评论输入区 |
| **结果** | 页面聚焦于点检闭环本身 |
| **验收** | 这些字段/区域不再展示；**「点检人」字段的数据本身仍需在后台维护**（权限与创建人取值依赖它，见 Q-04） |

## REQ-TASK-010 · 点检任务详情页展示继承的路径信息

| 要素 | 内容 |
|---|---|
| **角色** | 点检任务查看者 |
| **场景** | 从点检任务进入详情时，需要知道它属于哪个业务上下文 |
| **行为** | 详情页展示继承的路径：`项目 / 交付物计划 / 阶段 / 原始任务名称` |
| **结果** | 路径格式与原始任务详情页一致；可返回原始任务 |
| **验收** | 层级与路径样式**沿用系统现有通用交互**，不使用平铺展开效果；反馈弹窗顶部信息块与路径面包屑回显的是**原始任务标题**（而非点检任务标题） |

## 全局约束（贯穿所有条目）

| # | 约束 | 出处 |
|---|---|---|
| 1 | **不改造原始任务现有页面逻辑与其他页签** | PRD §4.8、§6.1 |
| 2 | **不改造低码配置部分**——新增页签走硬编码（在现有低码配置表单基础上新增写死的页签） | PRD §6.1 |
| 3 | **生成间隔与完成偏移是配置项**，不硬编码，也不在任务上新增「节点时间」类字段 | PRD §4.1.3、§7 |
| 4 | 样式沿用 V-IPD 现有组件与样式，保持视觉与交互一致 | PRD §6.2 |
| 5 | 不影响现有任务反馈、任务列表、任务详情等既有功能 | PRD §7 |
| 6 | 点检任务与原始任务的**关联关系必须落库** | PRD §7 |

## 术语对照

| 术语 | 含义 |
|---|---|
| 原始任务 | 被点检的任务（点检任务以外的所有任务类型） |
| 点检任务 | 由原始任务派生、用于周期性跟踪进度的任务，任务类型固定为「点检任务」 |
| 点检人 | 原始任务上配置的点检负责人；手动生成按钮的权限主体，也是点检任务的创建人 |
| 生成间隔 | 两次点检任务之间的间隔天数，可配置（标准周期 14 天） |
| 完成偏移 | 点检任务 `计划完成 = 计划开始 + N 天` 中的 N，可配置 |
| 回写 | 把点检任务反馈的进度与说明写入原始任务的实际进度与反馈信息 |

> ⚠️ **一处与原型不一致，以实现为准**：Demo 原型里点检任务的创建人写的是「系统」，
> 与会议结论不符。**以 PRD §4.1.4 为准：创建人 = 原始任务的点检人。**
