## STD-PRJ-V-IPD-017 · Vue 2.6 项目，禁止使用 Vue 3 语法

<!-- meta
tier: resident
scope: 写前端代码、评审
frozen: false
-->

**规则**：前端是 **Vue 2.6.14（EOL，无升级计划）**，禁止使用 Vue 3 语法：`<script setup>`、`defineProps`、组合式 API、`ref`/`reactive` 的 Vue 3 语义、多根组件模板。

**原因**：EOL 不等于会升级——本项目明确不升。写了 Vue 3 语法**编译期就会失败**（这是好消息）；但把 Vue 3 的组合式思维用在 Vue 2 上（如以为 `reactive` 可用）会在运行期才暴露。UI 库同理：**Element UI 2.15（不是 Element Plus）**。

## STD-PRJ-V-IPD-018 · 平台菜单 `defaultUrl` 不带 `.vue` 后缀

<!-- meta
tier: resident
scope: 配置菜单、排查 404
frozen: false
-->

**规则**：平台菜单的 `defaultUrl` 写成 `/experience/voc/index`，**不要写 `/experience/voc/index.vue`**。

**原因**：带后缀会让 `src/router/utils.js` 的 `getComputedUrl` 里 `require` 失败，被 `catch` **吞掉后静默降级到 `/system/error/404`**。症状是：**Console 无任何报错**，看起来像路由配错了——排查方向会被带到路由定义上去。约定等价品见 `errorUrl = '/system/error/404'`。

## STD-PRJ-V-IPD-019 · UI 库：Element UI 为主；表格新功能优先 Element UI + VXE Table

<!-- meta
tier: indexed
scope: 新增页面、选表格方案
frozen: false
-->

**规则**：**Element UI 为主库**；Ant Design Vue 仅在已在使用它的特定模块里继续用。表格有四套并存（VXE Table / Handsontable / VTable / Ant Design Vue），**新功能优先 Element UI + VXE Table**；Handsontable 用于类 Excel 编辑，VTable 用于高性能大数据展示。

**原因**：四套表格方案是历史形成的，不是选型结果。**同一页面内不得混用同类 UI 库组件**（见技术栈包 `fe-vue2-elementui` 的 `STD-VUE2-002`）——混用的后果是同一个页面上出现两种间距、两种表单校验行为。

## STD-PRJ-V-IPD-020 · 前端构建与启动必须带 `--openssl-legacy-provider`，构建还需 8GB 堆

<!-- meta
tier: resident
scope: 构建、本地启动、排查 OOM
frozen: false
-->

**规则**：
```
NODE_OPTIONS = "--openssl-legacy-provider --max-old-space-size=8192"
```
两个参数**都不能省**：
- **`--openssl-legacy-provider`**：Node 17+ 下 webpack 老 loader 用了 OpenSSL 3 已废弃的 MD4，不加报 `digital envelope routines::unsupported`
- **`--max-old-space-size=8192`**：不加会 **OOM（exit 134）**。实测生产构建 5m14s

**内存策略（16GB 机器）**：不要同时启动 12 个 Java 服务 + 前端首编译（会 OOM 全挂）。内存不足时**先停 Java**，等前端编译完（`http://localhost:9528/` 返回 200）再起 Java。

**原因**：这两个参数在 `pnpm run dev2` 里已带，但 **`build` 脚本里没有**——直接跑 `pnpm run build` 会 OOM。
