## STD-PRJ-V-IPD-007 · 配置优先 Nacos，且禁止提交明文密钥

<!-- meta
tier: resident
scope: 配置文件变更
-->

**规则**：配置优先从 Nacos 读取，**不把地址写死在代码里**。二期 `application-{env}.yml` 用环境变量全覆盖（`${VAR:default}`），Nacos import 用 `optional:nacos:<app>[-<profile>].yml`（group `ppExploit`）。
**新增配置不得提交明文密钥**——数据库口令、Redis / Nacos 口令、飞书 secret、第三方 api-key 一律通过环境变量或 Nacos 加密配置注入。

**一个必须知道的事实**：**仓库里的 yml 大多是壳，真实配置在 Nacos**。所以"本地改了 yml 就生效"是错的（还要同步 `target/classes`，见 `STD-PRJ-V-IPD-024`）。

**原因**：`git log` 里一旦出现明文密钥，**它就在历史里永久存在**——删除当前文件的密钥不算修复，只能轮换密钥，而轮换生产密钥是有停机风险的动作。见基线 `STD-BASE-104`。

## STD-PRJ-V-IPD-021 · 本地 Redis 必须用 db3

<!-- meta
tier: resident
scope: 本地启动、排查 REQUEST_408
-->

**规则**：本地开发的 Redis **必须用 db3**（地址 `10.82.71.250:6379`）。一期改 `application-local-base.yml` 的**两处** `database`；二期 7 个模块的 `application-local.yml` 默认值已于 2026-10-09 统一改为 db3。

**原因**：dev 的 K8s ConfigMap 设 `SPRING_REDIS_DATABASE=3`，**OAuth 把 token context 写在 db3**，本地若用其他 db，应用 Redis 与认证中心 Redis 不是同一个，报 `REQUEST_408`。错误信息完全没提 db 编号——排查方向会被带到"Token 失效"或"服务没起来"上去。

## STD-PRJ-V-IPD-022 · local 必须关闭 GatewayFilter

<!-- meta
tier: resident
scope: 本地启动、排查「非法请求」
-->

**规则**：local profile 下必须设 `client.gateway.disable: true`（一期在共享配置 `application-local-base.yml`）。

**原因**：GatewayFilter 校验请求是否带网关密钥 header，而本地 vue proxy 直连**不经过网关**，于是访问被拦、登录报「非法请求」（错误码 `6010101`）。**改完必须同步到 `target/classes`**（见 `STD-PRJ-V-IPD-024`）。

## STD-PRJ-V-IPD-023 · 本地 Java 服务必须显式设 `-Xmx`

<!-- meta
tier: resident
scope: 本地启动、排查进程无声挂掉
-->

**规则**：本地启动 Java 服务**必须显式指定堆上限**：一期 `-Xmx512m`，二期 `-Xmx256m`。

**原因**：JVM 默认堆 = 物理内存 1/4。16GB 机器上就是 **4GB/服务**，12 个服务 × 4GB 必然全挂。失败形态是**进程无声消失**（不是抛异常），日志里什么都看不到——看起来像"启动脚本没跑"，实际是 OOM。

## STD-PRJ-V-IPD-024 · 改配置后必须同步到 `target/classes`

<!-- meta
tier: resident
scope: 改任何 yml / 配置
-->

**规则**：改完配置**必须同步复制到 `target/classes`**（或重新构建），否则不生效。

**原因**：本地启动用的是**旧构建打出的 jar**，新写的配置不在里面。症状是"配置明明改了却没生效"，而排查方向通常会被带到"配置项名字写错了"上去。这条与 `STD-PRJ-V-IPD-007`（真实配置在 Nacos）是同一类问题的两面。

## STD-PRJ-V-IPD-025 · 二期 experience 端口是 18082，不要改回 18083

<!-- meta
tier: indexed
scope: 改端口、排查端口冲突
-->

**规则**：二期 7 个服务端口固定为 performance 18081 / **experience 18082** / dvp 18083 / experience-issue 18084 / specialised-parts 18085 / competitor 18086 / cmf 18087。

**原因**：`pp-experience-root` 与 `pp-dvp-root` 曾**默认端口同为 18083**，本地无法并行启动。experience 已改为 18082。**改回去会让两个模块再次冲突**，且冲突只在同时启动时才暴露。

## STD-PRJ-V-IPD-026 · 测试账号与凭据的使用规范

<!-- meta
tier: indexed
scope: 用测试环境、准备测试数据
-->

**规则**：
- 测试账号**严禁用于生产**；同一系统不同环境账号独立管理，不混用
- **UAT 只读**：`https://core-test.voyah.cn/` 上禁止创建 / 修改 / 删除任何数据，退出登录等会话操作允许
- 测试数据加前缀（见 `STD-PRJ-V-IPD-027`），测完**逻辑删除**不物理删
- **口令不写进文档与仓库**——统一存密码保险柜，应用侧从环境变量或 Nacos 加密配置取
- 生产账号密码不在任何文档明文

**原因**：这是知识库基线条目 `STD-BASE-104` 在项目侧的具体化。**口令散在文档里是泄漏面，不是便利**——记录口令的位置只有一处，改了也只改一处。UAT 是共享环境，改数据会影响别人的验证结论。
