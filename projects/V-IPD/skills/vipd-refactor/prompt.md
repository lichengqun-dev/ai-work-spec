# 指令：V-IPD 重构操作规范

## 你要做的事

用户要在 V-IPD 的重构分支上写代码时，**先读规范再动手**，改完按检查清单自检。

## ⚠️ 先确认前置是否就位（不确认就别往下走）

本 Skill 按 **`spec/` / `constraints/` / `standards/` / `guides/` 四层文档**组织。
**这四层目录在本工作区不存在**（它是目标态知识库的结构）。

所以第一步：**确认这些文档在哪、是否可读**。找不到就**停下来告诉用户缺什么**，
不要凭 SKILL.md 里那几行摘要去写代码——那几行是导航，不是规范本身。

同样要确认的：SKILL.md 里写的检查命令针对的仓库布局（`*/pom.xml`、`cn.voyah.vipd` 命名空间、
`vipd-legacy`）**与当前 `pp-powerproject-extend` 的 `com.pp` / `pp-*-root` 布局不一致**。
先问清用户这次改的是**哪个仓、哪个分支**。

## 四层文档的分工（决定一条规范能不能改）

| 层 | 回答什么 | 变更流程 |
|---|---|---|
| `spec/` | 是什么 | 架构评审 |
| `constraints/` | **不能做什么** | **不可变更**（除非用户明确要求） |
| `standards/` | 怎么写 | 技术评审 |
| `guides/` | 怎么做某件事 | 团队协商 |

**`constraints/` 是红线**——用户没明确要求时不要挑战它，也不要"顺手"放宽。

## 提交前的自检清单（六项，逐项给结果）

照 SKILL.md 的命令逐条跑，**每条都要给出实际输出，不要只说"应该是空的"**：

1. 无供应商依赖（`pom.xml` 里无 `com.ak.iform` / `com.aoborsoft` / `com.baomidou`）
2. 无供应商包名 import
3. 包名全在新命名空间（`vipd-legacy` 除外）
4. 每个服务只有一个启动类
5. 数据库字段无尾下划线（`create_by_` / `update_by_` / `deleted_`）
6. 逻辑删除不再用 `deleted_='N'` 形态

## 你绝对不要做的事

- **不要在四层文档缺失时凭记忆写代码**
- **不要放宽 `constraints/`**，除非用户当次明确要求
- **不要把检查清单里"期望为空"的项跳过**——空集和"没查"看起来一样，**要贴出实际执行的命令与输出**
- 不要执行 git 操作

## 输出格式

```
前置确认：四层文档 <位置> ✅ / ❌（缺 <哪一层>）
本次仓库：<仓> / <分支>

提交前自检：
  1 无供应商依赖      grep ... → 空 ✅
  2 无供应商 import   grep ... → 空 ✅
  3 包名新命名空间    → 空 ✅ / N 处 ❌（列出）
  4 每服务一个启动类  → 每模块恰好 1 ✅
  5 字段无尾下划线    → 空 ✅ / N 处 ❌
  6 逻辑删除形态      → 空 ✅ / N 处 ❌

<有 ❌ 的逐条给修法>
```
