# projects/_template —— 新项目的空骨架

> 复制本目录为 `projects/<项目码>/`，填 `.agent/project.yaml`，然后调用 `ai-spec-build`。

## 复制后你会得到

```
projects/<项目码>/
├── README.md               项目索引：读什么、怎么定位需求落点
├── <项目级文档>.md          架构 / 模块 / 模型 / 规范 / 环境等 —— **散文**
│                           人读的，人工维护或 AI 梳理后产出，**不按编号约定写**
├── skills/                 项目级 Skill（空骨架）
└── .agent/                 本项目的机器面（空骨架）
    ├── project.yaml        组合声明 —— **必填**，其余都可后补
    ├── rules/              带编号的项目级条目 —— **进生效快照**（由散文提炼而来，一源一文件）
    ├── state/              ← 从 projects/_template/.agent/state/_模板.yaml 复制批次状态模板
    ├── index/              功能编号总表 · 依赖关系图 · 快车道台账 · 技术债清单
    ├── memory/             跨批次沉淀的项目约定
    ├── spec-effective/     生效规范快照（生成物，不入库）
    └── logs/               执行日志（不入库）
```

## 接入的硬门槛只有一条

**`.agent/project.yaml` 填对**——其余内容（项目级文档、状态文件、需求目录）都可以后补：

| 内容 | 什么时候补 |
|---|---|
| `.agent/project.yaml` | **接入时必须**（否则 `ai-spec-build` 编译不出快照） |
| 项目级文档（架构 / 模块 / 模型 / 测试策略 / 环境） | 接入后尽早。**没有它们，AI 定位需求落点时只能靠猜** |
| `.agent/state/<批次号>.yaml` | 第一个批次开始时（由 `ai-requirement-00-intake` 创建） |
| `<需求名>/` 产出物目录 | 第一个批次开始时（由 `ai-requirement-01-init` 创建） |
| `skills/` | 出现"每次都要交代一遍"的操作时 |

## 项目级文档怎么写

**散文随便写——不用管编号、不用管格式。** 这就是把散文和条目分两层的目的。

写完（或从别处复制进来、或让 AI 梳理代码仓产出）之后，**调用 `ai-spec-extract`** 把里面的约束摘成
带编号的条目，落到 `.agent/rules/`。之后构建才读得到它们。

| 层 | 谁写 | 要不要按格式 |
|---|---|---|
| `projects/<项目码>/*.md`（散文） | 人，或 AI 梳理后给人确认 | **不要**——自由格式 |
| `.agent/rules/*.md`（条目） | `ai-spec-extract` 摘录 | 是（脚本要解析） |

**判据**（决定一段话该不该被摘成条目）：它约束的是不是一个**可判定的行为**？
是 → 条目；描述现状、导航、待办清单 → 留在散文里。
拿不准时不用自己纠结，`ai-spec-extract` 会逐段给结论清单让你核对。

散文里的规则**照抄**进条目，不改一个实词——理由见该 Skill 的 `references/摘录判据与反例.md`。

## 建项目级规范的取材顺序

1. **读代码**——构建文件、配置、目录结构。技术栈、模块划分、环境地址都能从这里取到
2. **读项目已有文档**——很多项目仓里已经有系统梳理文档，比从头写准确
3. **只写核实过的**——不确定的标「待填」，不要编。**编一份似是而非的架构文档，比没有更糟**：
   它会成为后续所有人的错误前提

## 关于 `.agent/` 的两份机制文件

**批次状态模板与日志格式约定就住在本骨架里**，不在别处：

- `projects/_template/.agent/state/_模板.yaml` —— 批次状态 Schema（全库共用的）
- `projects/_template/.agent/logs/README.md` —— 日志格式约定

放在骨架里而不是单独放顶层，是因为**复制 `_template` 就该得到一个结构完整、可直接开工的项目目录**。
模板散在别处时，新接入的人会漏掉它们。

本项目自己的批次状态、编号总表、台账都放 `projects/<项目码>/.agent/` 下——
**编号总表必须是项目级的**，两个项目用同一个模块码时全局共表会撞号。
