> 存放**跨批次复用**的领域约定与历史决策。
> 与规范包的区别：这里的条目**尚未稳定到可以成为规范**，先在这里观察。
> 当某条约定在 3 个以上批次中被反复引用，走 `ai-spec-promote` 提升为包条目或基线。

## 什么内容该记在这里

- 一次评审会上达成、但尚未形成条目的共识（如"这块先这样，下个迭代再看"）
- 某个历史决策的**原因**（"为什么导出接口没做分页"）
- 领域黑话与内部简称的对照（很多术语只存在于口头，新人无法从代码看懂）

## 什么内容不该记在这里

| 内容 | 应该放哪 |
|---|---|
| 已成为规范的约束 | 规范包或各域 `standards/` |
| 只在本批次有效的临时决定 | `projects/<项目码>/.agent/state/<批次号>.yaml` |
| 某个功能的实现细节 | 项目文档仓的设计文档 |

## 条目格式

```markdown
## [YYYY-MM-DD] <约定标题>

**内容**：……

**原因**：……（这条最重要。没有原因的历史约定，半年后没人敢动它）

**相关批次**：<批次号>（若已在多个批次中出现，列出全部）
```
