# 功能编号总表

> **这是整条追溯链的主键表。** 任何 Skill 不得自行生成编号，必须向本表申请。
> 格式与校验规则见 `../../../00_工作空间配置/命名与编号规范.md`。
>
> **本表是项目级的** —— 它在 `projects/<项目码>/.agent/index/` 下，不是全库共用一张。
> 两个项目都用同一个模块码（如 `TASK`）时，全局共表会撞号，而"编号一经启用不复用"是这条链的根基。

## 使用方式

| 场景 | 动作 |
|---|---|
| 新增需求条目 | 在「需求条目」段追加 `REQ-<模块码>-<三位>`，序号取该模块当前最大值 +1 |
| 新增功能点 | 在「功能点」段追加 `FR-...`，`来源 REQ` 列必填 |
| 功能行为修改（迭代） | 新增 `FR-<原编号>-D<n>`，不修改原条目 |
| 归档批次 | 填写「批次」列，供 gate-06 断链检测 |
| 编号废弃 | 保留行，状态列改 `[已废弃]`，**不回收编号** |

**编号一经启用不复用。** 删除条目时保留编号并标记，不回收——回收会让历史文档中的引用指向错误的对象。

## 功能点

| 编号 | 描述 | 来源 REQ | 设计章节 | 覆盖用例 | 提交 | 状态 | 批次 |
|---|---|---|---|---|---|---|---|
| _示例_ `FR-XXX-001` | | | | | | | |

**列含义**：
- `设计章节`：详细设计文档中的小节号，如 `§5.4`
- `覆盖用例`：`TC-<本编号>-<两位>`，多个用 `,` 分隔
- `提交`：实现该功能的 commit hash 或 PR 号
- 后三列由 Skill 在对应阶段自动回填，**不允许人工估算填写**
