# 能力声明

把原始需求（会议记录 / 工单 / 口头描述）**结构化为标准化的需求文档集**。

**不负责原型产出，不负责 PRD 撰写。** 这两件事属于 03 / 04。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 原始需求材料 | 用户提供 / 项目文档仓 `inbox/` | 是 | 非空，含业务目标描述 |
| 批次上下文 | `ai-requirement-01-init` 产出（L3 CLAUDE.md） | 是 | 存在 |
| 业务场景清单 | `references/业务场景清单.md` | 是 | 存在（可为空骨架） |
| 需求分析规范范本 | `references/需求分析规范范本.md` | 是 | 存在 |
| 功能编号总表 | `.ai/index/功能编号总表.md` | 是 | 存在，用于申请 `REQ` / `FN` 编号 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 原始需求格式化 | 文档仓 `docs/01_需求/原始需求格式化.md` | 条目带 `REQ` 编号 |
| 需求功能分析 | 文档仓 `docs/01_需求/需求功能分析.md` | 每个功能有 `FN` 编号，标注来源 `REQ` |
| 需求问题汇总 | 文档仓 `docs/01_需求/需求问题汇总.md` | 待澄清问题清单 |
| 编号登记 | `.ai/index/功能编号总表.md` | 追加新申请编号 |

## 前置条件（不满足则拒绝执行）

- 批次状态文件 `current_step` 为 `analysis`
- gate-01 需求准入已通过（**未通过时拒绝执行**，不要在需求目标不明的情况下做结构化）
- 目标产出文件已存在 → 走"续做"分支，不覆盖

## 执行步骤

1. 读原始需求材料，逐条提取需求条目，**向总表申请 `REQ` 编号**
2. 对照业务场景清单归类，识别前提、主流程、异常流程、边界
3. 推导功能清单，**申请 `FN` 编号**，逐条标注来源 `REQ`
4. 无法确定的信息 → 记入待澄清清单，**不臆造**
5. 校验产出完整性（FN 是否都有来源、编号是否都已登记）
6. 回写状态文件

## 边界（明确不做）

- 不生成原型、不撰写 PRD
- 不做技术方案设计（不选技术栈、不定数据模型）
- 不修改已归档的历史批次文档
- 不评估工作量

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 原始需求信息量不足以识别功能 | **停在中途**，输出待澄清清单，等待人工补充 |
| 功能编号冲突 | 报错退出，**不自动重新编号** |
| 业务场景无法归类 | 标为"场景待定"，记入问题汇总（不要硬塞进最近的场景） |
| 批次上下文缺失 | 提示先执行 `ai-requirement-01-init` |
