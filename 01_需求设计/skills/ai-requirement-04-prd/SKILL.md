# 能力声明

**读取原型工程**，生成 PRD 与页面原型映射表。

核心机制是"AI 读原型生成 PRD"——因为原型里带着 `data-fn` 标记，它比任何文字描述都更接近需求的事实。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 原型工程 | `ai-requirement-03-prototype` 产出 | 是 | 页面元素带 `data-fn` 标记 |
| 需求功能分析 | `ai-requirement-02-analysis` 产出 | 是 | 每个功能有 `FN` 编号 |
| PRD 模板 | `templates/PRD 模板.md` | 是 | 存在 |
| 需求问题汇总 | 02-analysis 产出 | 是 | 存在 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| PRD | 文档仓 `<需求名>/01_需求/PRD.md` | 按模板；每个功能一节，标注 `FN` |
| 页面原型映射表 | 文档仓 `<需求名>/01_需求/页面原型映射表.md` | `PAGE` ↔ `FN` ↔ PRD 章节 |

## 前置条件（不满足则拒绝执行）

- gate-02 原型确认已通过（**未通过时拒绝**——原型还没被业务方确认，据此生成的 PRD 会白写）
- 原型工程中 `data-fn` 标记覆盖全部 `FN`（缺失时列出，由人确认是否可忽略）

## 执行步骤

1. 遍历原型页面，提取 `data-fn` 标记与页面结构
2. 逐个 `FN` 生成 PRD 章节：功能描述、交互说明、字段说明、异常提示、验收要点
3. 生成页面原型映射表
4. 交叉校验：PRD 中的每个 `FN` 在原型中是否有对应页面；反之亦然
5. 把未解决的问题标注为"待确认"引用问题汇总，**不自行填补**

## 边界（明确不做）

- 不做技术方案、不写接口设计、不定数据模型
- 不修改原型（发现原型有问题应回到 03）
- **不解决待澄清问题**——把它们原样带入 PRD 的"待确认事项"节

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 原型中 `data-fn` 标记缺失 | 列出缺失清单，询问用户是否继续（继续则对应章节标注"原型未体现"） |
| PRD 与原型不一致 | 以**原型**为准，并在报告中标出不一致处供人复核 |
| 待澄清问题仍存在 | 不阻断，但必须在 PRD 中列为待确认事项 |
