# 能力声明

把外部设计稿（Figma / Axure 导出物）转成**与 `ai-requirement-03-prototype` 同构的原型产出**，
并补齐 `data-fn` 标记。

**"同构"是硬要求**：`ai-requirement-04-prd` 靠遍历原型的 `data-fn` 标记生成 PRD。
两条路径（自画原型 / 外部设计稿）的产出格式必须一致，否则 04-prd 只认其中一条。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 设计稿导出物 | 用户提供 | 是 | Figma JSON / Axure HTML 导出 / 切图 + 标注，可解析 |
| 需求功能分析 | `ai-requirement-02-analysis` 产出 | 是 | 每个功能有 `FN` 编号——**用于补齐标记** |
| 原型工程仓 | `ai-requirement-01-init` 产出 | 是 | 目标落点 |
| 生效规范快照 | `.ai/spec-effective/<项目码>.md` | 是 | 目标前端技术栈从这里读 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 原型页面 | 原型工程仓 | **与 `ai-requirement-03-prototype` 同构**：可运行、每个可交互元素带 `data-fn` |
| 标记补齐说明 | 项目文档仓 `docs/01_需求/原型标记补齐说明.md` | 哪些元素无法映射到 FN、需人工确认 |
| 原型规划（补充） | 项目文档仓 `docs/01_需求/原型规划.md` | 与 03-prototype 合并——页面清单与 `PAGE` 编号 |

## 前置条件（不满足则拒绝执行）

- 需求功能分析已产出，且每个功能有 `FN` 编号（无编号则**拒绝**——没有编号就无从补标记）
- **原型格式基准已存在**：`ai-requirement-03-prototype` 的产出契约是格式基准；
  若该 Skill 尚未产出过任何原型，本 Skill 应先读它的 `SKILL.md` 与产出契约，确认格式后再动手
- 生效快照中 `fe` 维度的规范包存在（技术栈未知时**拒绝**，不要自己选一套）

## 执行步骤

1. 解析设计稿，提取页面结构与可交互元素
2. 按生效快照的前端技术栈生成原型代码（**不自行选型**）
3. **补齐 `data-fn` 标记**：对照需求功能分析，为每个可交互元素标注它服务的 `FN`
4. 无法确定归属的元素 → 列入「待人工确认」清单，**不猜**
5. 申请 `PAGE` 编号并补进原型规划
6. 自检：产出与 03-prototype 的格式是否一致（同构性检查，见下）
7. 回写批次状态文件

## 同构性检查（产出后必做）

对比 `ai-requirement-03-prototype` 产出契约，逐项确认：

| 项 | 要求 |
|---|---|
| 可运行 | 能启动、主流程能走通 |
| `data-fn` 标记 | 每个可交互元素带，且取值是合法 `FN` 编号 |
| 目录结构 | 与 03-prototype 的产出同构（不新造一套目录风格） |
| 页面清单 | 已在 `原型规划.md` 中登记 `PAGE` 编号 |

**任一项不满足就报告，不要"先这样，反正能看"** —— 04-prd 是按格式解析的，
格式不一致的后果是 PRD 生成不出来，而那时已经过了原型确认这道门禁。

## 边界（明确不做）

- **不做像素级复刻**。目标是**信息结构与交互路径**可验证，不是美术还原——
  配色、圆角、动效的实现成本高且一定会被真实实现替换
- 不产出 PRD（那是 `ai-requirement-04-prd`）
- **不猜测 `data-fn` 归属**。无法确定的元素一律列入待确认清单——猜错的标记会让 04-prd 生成错误的功能章节，而错误会被下游一路放大
- 不修改 `ai-requirement-03-prototype` 的产出

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 设计稿无法解析 | 说明需要哪种导出格式，停止 |
| 元素无法映射到任何 `FN` | 列入待确认清单；**若整个页面都映射不上，说明需求分析漏了这一块**——回去补 |
| 设计稿与需求功能分析冲突（稿里有需求没有的功能） | **停止并报告**。这可能是需求遗漏，也可能是设计稿画多了——两种都要人判断 |
| 目标技术栈不明确 | 提示先运行 `ai-spec-build`，中止 |
| 产出无法与 03-prototype 同构 | 报告差异点，不要强行交付 |

## 与其他 Skill 的关系

- 上游：`ai-requirement-02-analysis`、外部设计稿
- 下游：`ai-requirement-04-prd`（**依赖本 Skill 的产出格式与 03-prototype 一致**）
- 与 `ai-requirement-03-prototype` 是**并列关系**：一个从需求画原型，一个从设计稿转原型，
  两者产出的格式必须同构
