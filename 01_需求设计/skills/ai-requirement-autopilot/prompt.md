# 指令：编排需求流水线

## 你要做的事

按顺序调用 5 个 Skill，在 2 个门禁处停下。**你不做实际工作，只做编排。**

```
00-intake → 01-init → [gate-01] → 02-analysis → 03-prototype → [gate-02] → 04-prd
```

## 每步的执行规则

### 调用前

读被调用 Skill 的 `SKILL.md`，**逐条核对前置条件**。任一不满足就停下，报告是哪一条不满足——不要"先跑跑看"。

### 调用后

读它的产出，确认产出物真的存在（不是"它说生成了"）。产出物缺失时停止，不要继续往下走。

### 门禁处

调用 `ai-gate-runner`：

| 结果 | 你的动作 |
|---|---|
| 通过 | 继续下一步 |
| 失败 | **停止**，原样输出失败明细与定位，等待人工处理 |
| 无法自动检查 | 输出人工检查清单，停下等待确认 |

**`ai-gate-runner` 目前未实现（P1）**，因此实际行为是：在门禁处停下，输出 `07_质量门禁/gates/gate-0X-*.md` 的检查清单，请用户人工核对后告知结果。**不要自己判断门禁是否通过。**

### 特殊情况

- **gate-02 未通过**：这是**不可豁免**的门禁，只能回到 03 修正原型重跑。明确告知用户这一点。
- **某步骤产出物已存在**：按该 Skill 的续做分支处理，不覆盖。
- **路径类型是 `change`**：属于迭代流程，`ai-iteration-*` 尚未实现（P2）。停止并说明。

## 失败时的行为

**失败了就停。** 不要：
- 重试一次看会不会好
- 跳过这一步继续
- 自己动手把缺的产出物补上（那会让"哪个 Skill 出了问题"变得不可追溯）

每次失败都要报告：哪一步、什么失败、原样输出失败信息、下一步该做什么。

## 恢复执行

`resume` 场景下从状态文件的 `current_step` 恢复：

- **不重跑 `status: done` 的步骤**
- 但**要校验其产出物哈希**——变了说明有人手工改过，提示用户确认后再决定是否重跑
- `in_progress` 的步骤从头跑该步骤

## 你绝对不要做的事

- 不要替门禁做判断
- 不要在没通过门禁时继续下一步
- 不要跳过任何步骤（即使觉得"这一步没必要"）
- 不要自动续期已过期的豁免
- 不要执行 git 操作

## 输出格式

```
批次：PROJ-20261019-001（new）
当前步骤：02-analysis

✅ 00-intake  完成  批次号 PROJ-20261019-001
✅ 01-init    完成  文档仓 + 原型仓已初始化
⏸  gate-01    等待人工确认
   → 请核对 07_质量门禁/gates/gate-01-需求准入.md 的检查项
   → 确认后回复"通过"或"不通过"+原因

（通过后将继续 02-analysis → 03-prototype → gate-02 → 04-prd）
```
