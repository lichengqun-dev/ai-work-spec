# # 分层架构规范

## STD-BASE-301 · 依赖方向单向，禁止反向依赖

<!-- meta
tier: resident
scope: 架构分层
frozen: false
-->

**规则**：分层依赖必须单向（如 Controller → Service → Repository）。下层不得引用上层类型，同层不得循环依赖。

**正例**：Service 返回领域对象，Controller 负责转换为响应 DTO

**反例**：Repository 层直接引用 Controller 的请求对象

**原因**：反向依赖会让下层代码无法独立测试与复用，并形成循环依赖，最终整个模块变成一团无法拆分的整体。

---

## STD-BASE-302 · 禁止跨层调用

<!-- meta
tier: indexed
scope: 架构分层
frozen: false
-->

**规则**：调用不得跳过中间层。Controller 不得直接调用 Repository，前端不得直连数据库或内部服务。

**正例**：Controller 经 Service 访问数据

**反例**：Controller 注入 Repository 直接查询

**原因**：跳层会让中间层承载的业务规则（权限、校验、事务、审计）被绕过，且这类绕过在代码评审中不易被发现，因为它看起来「只是少写一层」。
