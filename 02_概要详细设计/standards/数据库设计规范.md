# 数据库设计规范

## STD-BASE-311 · DDL 变更必须提供回滚脚本

<!-- meta
tier: resident
scope: 数据库变更
frozen: false
-->

**规则**：任何 DDL 变更（建表、加字段、改类型、加索引）必须同时提供可执行的回滚脚本，并与正向脚本一同提交评审。

**正例**：`migrate.sql` 与 `rollback.sql` 成对提交

**反例**：只提交 `ALTER TABLE … ADD COLUMN`，回滚靠「手工改回去」

**原因**：上线出问题时没有时间现场推导回滚语句。回滚脚本必须在变更前写好并由他人验证过。

## STD-BASE-312 · 表与字段必须有注释

<!-- meta
tier: indexed
scope: 数据库设计
frozen: false
-->

**规则**：新建的表和字段必须有注释，说明业务含义。枚举型字段必须写明取值含义。

**正例**：`status TINYINT COMMENT '状态：1-草稿 2-已提交 3-已归档'`

**反例**：字段名 `type`、`flag`、`status` 无注释，靠读代码反推取值

**原因**：字段含义只存在于开发者记忆中，人一换就成了不可知数据。此外注释是 AI 生成代码与 SQL 的关键上下文来源。

---

## STD-BASE-313 · 高频查询条件必须有索引

<!-- meta
tier: indexed
scope: 索引设计
frozen: false
-->

**规则**：出现在高频查询 `WHERE` / `JOIN` / `ORDER BY` 中的字段必须有索引覆盖；新增索引需评估写入放大的代价。

**正例**：对列表页的筛选字段建组合索引，顺序与查询条件一致

**反例**：等上线后出现慢查询再补索引

**原因**：缺索引的问题在开发阶段因数据量小而不暴露，上线后表现为接口超时，且此时补索引才是真的影响生产。
