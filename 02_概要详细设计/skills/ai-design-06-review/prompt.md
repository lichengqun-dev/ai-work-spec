# 指令：执行设计评审并冻结契约

## 你要做的事

读设计阶段的产出，跑 gate-03，然后按结果决定下一步。**你不做检查项判断。**

```bash
S=07_质量门禁/skills/ai-gate-runner/scripts/gate_run.py
python3 $S --project <项目码> --batch <批次号> --gate gate-03
```

## 跑完之后逐条读输出

执行器的输出里有四类信息，**每一类都要如实转达，不要总结成"评审已完成"**：

| 输出 | 你该做什么 |
|---|---|
| `✅ pass` | 无需处理 |
| `❌ fail` | **原样读出明细**（执行器已给出具体对象，如"缺失 FN-CORE-045"），并给出修正方向 |
| `⏭️ skip` | 连同"要做什么才能自动校验"一起读出。**`skip` 不是通过** |
| 人工核对清单 | 原样列出。**不替用户判断这些项过不过** |

## 按结果分支

```
failed          → 停止。输出未通过项 + 定位。等修正后重跑。
pending_manual  → 请用户核对清单后签核，给出命令：
                  python3 $S ... --gate gate-03 --confirm --by <名字>
passed          → 执行契约冻结（见下）
```

**`--by` 必须是真实人名。** 门禁记录的价值在于能回答"谁在什么时候确认的"，
填 `auto`、`admin` 等于没留痕。

## 契约冻结要落成可核对的东西

`passed` 之后不要只说一句"契约已冻结"，要实际做四件事：

1. 计算 `docs/02_设计/接口契约.yaml` 的哈希，写入批次状态文件，附冻结时间
2. 在 `docs/02_设计/评审记录.md` 写：评审结论、参与人、未通过项及其处置（若曾失败过）
3. 更新批次状态文件：`review` 步骤置 `done`
4. 提示用户"需要通知前后端负责人契约已冻结"

**哈希这一步不能省。** 它让"这个批次开发时用的是哪版契约"可被回答。
没有它，契约冻结就只是一句声明，而声明在三个月后无法作为依据。

## 用户要求放宽检查项时

不要照做。解释清楚：

- 自动检查项不通过 → 修产出物，不是修门禁
- 人工项拿不准 → 那是需要人判断的，不是"跳过"
- 确实要带风险上线 → 走豁免：`--waive --by <名字> --reason "<具体原因>" --expires <日期>`

**豁免的理由要具体**：反例"赶工期"，正例"客户要求当日上线，契约变更待下个批次补"。
`--expires` 不允许填很远的日期——那等于没填。

## 你绝对不要做的事

- **不要代替人判断人工检查项。**
- **不要把 `skip` 说成通过。**
- **不要为让门禁通过而改门禁定义、改状态文件或放宽检查项。** 门禁的价值全部来自"它说了真话"。
- **不要自己改设计产出物来消除失败项**——发现问题应回到对应 Skill 重做
- **不要在门禁未通过时推进到编码阶段。**
- 不要执行 git 操作
