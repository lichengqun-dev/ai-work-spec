# 能力声明

执行 **gate-03（设计评审 + 契约冻结）**，并在门禁通过后把接口契约置为冻结态。

**本 Skill 不做检查项判断。** 自动检查交给 `ai-gate-runner`，人工项原样列给人。
它只负责编排这一步、以及在通过后执行"冻结"这个有副作用的动作。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 批次状态文件 | `projects/<项目码>/.agent/state/<批次号>.yaml` | 是 | 设计阶段各步骤已 `done` |
| 设计产出物 | 项目文档仓 `<需求名>/02_设计/` | 是 | 已登记到状态文件的 `artifacts` |
| gate-03 定义 | `07_质量门禁/gates/gate-03-*.md` | 是 | 可解析 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | 用于确认校验基于哪版规范 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 门禁结果 | 批次状态文件 `gates[]` | 由 `ai-gate-runner` 写入 |
| 评审记录 | 项目文档仓 `<需求名>/02_设计/评审记录.md` | 评审结论、参与人、未通过项与处置 |
| 契约冻结标记 | 批次状态文件 | 记录冻结时间与契约哈希 |

## 前置条件（不满足则拒绝执行）

- gate-02 已通过
- 设计阶段的前序步骤（arch / detail / db / api / frontend-spec）均已 `done`
- **`ai-gate-runner` 已实现**（`status: implemented`）——未实现时拒绝，不要手工"模拟"一遍检查

## 执行步骤

1. **调用 `ai-gate-runner` 执行 gate-03**（说"跑 gate-03"即可）——本 Skill 不自己做检查项判断
2. **逐条读出执行器输出**，不总结成"已完成"：
   - 自动检查的 `fail` 项，原样读出明细（执行器已给出具体对象）
   - `skip` 项，连同"要做什么才能自动校验"一起读出——**`skip` 不是通过**
   - 人工核对清单原样列出，**不替人判断**
3. 门禁结果为 `failed` → 输出未通过项与定位，**停止**，等修正后重跑
4. 门禁结果为 `pending_manual` → 请人核对清单后签核（把执行器给出的核对清单原样转达给用户）
5. 签核通过后，**执行契约冻结**：
   - 记录契约文件的哈希与冻结时间到批次状态文件
   - 在 `<需求名>/02_设计/评审记录.md` 记录评审结论与参与人
6. 回写批次状态文件

## 边界（明确不做）

- **不做检查项判断。** 自动项交给执行器；人工项交给人。替人拍板会让门禁失去意义
- **不放宽检查项。** 不因为"这个项目特殊"就跳过某项——那正是门禁失效的方式
- 不修复产出物（发现设计问题应回到对应 Skill 重做）
- 不豁免。豁免必须由人显式提供批准人与复查日期
- 不改门禁定义

## 契约冻结的实际动作

冻结不是一句声明，要落成可核对的东西：

| 动作 | 落到哪 |
|---|---|
| 记录契约哈希 | 批次状态文件 |
| 记录冻结时间 | 批次状态文件 |
| 记录评审结论与参与人 | `<需求名>/02_设计/评审记录.md` |
| 通知前后端负责人 | 由人执行（本 Skill 只提示） |

**冻结后的变更走变更子批次**（`<原批次号>-C<n>`），原批次产出物保持不可变。

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 门禁 `failed` | 停止，输出未通过项与定位；**不尝试绕过** |
| 门禁 `pending_manual` 且人不确认 | 保持 `pending_manual`，不推进 |
| 执行器报"引用了未实现的检查项" | 报错停止——这是门禁定义的问题，需要修定义或补实现，**不要私自从定义里删掉那一项** |
| 契约文件缺失或哈希对不上 | 停止，提示"产出物被外部修改"，由人决定是否重跑上游 |
| 执行器拒绝执行（引用了未实现的检查项、或上一道门禁未通过） | 原样输出原因，提示需先补齐什么。**不要绕过执行器自己判断** |
