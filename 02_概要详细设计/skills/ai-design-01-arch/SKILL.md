# ai-design-01-arch · 架构设计

## 能力声明

依据 PRD 与需求功能分析产出**架构设计**：模块划分、依赖方向、关键选型，以及每个决策的理由。
每个关键选型产出一条 `DEC-<模块码>-<3位>` 编号的决策记录，写清**决策 + 被否决的选项 + 理由**。

**不产出详细设计、不设计表结构、不写代码。** 那些属于 `ai-design-02-detail` / `ai-design-03-db` 等下游步骤。

## 何时用 / 何时不用

- **用**：PRD 与需求功能分析已产出，要划分模块、标注依赖方向、记录关键选型决策时（设计的第一步）
- **不用**：只写某个功能的时序与状态流转（`ai-design-02-detail`）；只设计表结构（`ai-design-03-db`）；
  只定义接口契约（`ai-design-04-api`）；只规划页面（`ai-design-05-frontend-spec`）

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| PRD | `ai-requirement-04-prd` 产出 | 是 | 每个功能有 `FR` 编号 |
| 需求功能分析 | `ai-requirement-02-analysis` 产出 | 是 | 存在 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | **技术栈与依赖方向约束从这里读，不得自行选型** |
| 现有系统结构 | 项目仓 | 否 | 增量开发时读取，用于判断是否偏离既有分层 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 架构设计 | 项目文档仓 `<需求名>/02_设计/架构设计.md` | 含 `DEC-<模块码>-<3位>` 决策记录 |
| 决策登记 | 同文件「决策记录」节 | 每条含：决策、被否决的选项、理由 |

产出结构：

```markdown
# 架构设计

## 一、非功能需求
| 类别 | 要求 | 依据 |

## 二、模块划分
| 模块 | 职责 | 依赖 |
|---|---|---|

（依赖关系图或矩阵；标注禁止的依赖方向）

## 四、决策记录

**决策**：……
```

## 前置条件

**hard（不满足则拒绝执行）**

- PRD 已产出（每个功能有 `FR` 编号）
- 需求功能分析已产出
- 生效规范快照存在——**技术栈未知时拒绝执行，不要自己选一套**

**soft（不满足则提示，可继续）**

- 批次状态文件 `current_step` 为 `design`（或等价的设计阶段步骤）
- gate-02 原型确认已通过（未通过时产出物顶部标注「未经上游确认」）

## 执行步骤

1. 读 PRD，提取**非功能需求**（性能、并发量级、数据规模、可用性）
2. 读生效快照，确认可用技术栈与既有分层约束
3. 划分模块，标注模块间的**依赖方向**（符合 `STD-BASE-301`：单向、不跳层）
4. 对每个关键选型产出 `DEC` 编号的决策记录：**决策 + 被否决的选项 + 理由**
5. 标注本批次涉及哪些模块、哪些不涉及（后者的价值是防止设计蔓延）
6. 回写批次状态文件：把本步骤置 `done`，在 `artifacts` 中登记 `<需求名>/02_设计/架构设计.md` 及其哈希

### 决策记录的编号与检查

决策编号 `DEC-<模块码>-<3位>`，向 `projects/<项目码>/.agent/index/功能编号总表.md` 申请（或按项目约定登记）。

**gate-03 会校验设计类产出物中至少存在一个 `DEC` 编号**（检查项 `decision-recorded`，WARN 级）。
这不是格式要求——没有决策记录，架构文档就只是一份结论，无法回答"为什么是这样"。

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始
- soft 不满足时照常产出，并在产出物顶部标注「未经上游确认 —— <哪一条没满足>」
- 批次状态文件不可写（如未接入批次）时：产出物落到指定路径，跳过状态回写并在报告中说明

## 边界（明确不做）

- **不做技术选型。** 技术栈由生效规范快照决定；快照里没有的技术说明它不在本项目的规范覆盖范围内——
  **此时应停止并说明，而不是"先用着"**（用了没有规范包覆盖的技术，等于后续所有产出都失去约束依据）。
  选型确有调整必须走知识库流程，不在本 Skill 里决定
- 不设计表结构（03-db）、不定义接口（04-api）、不设计页面（05-frontend-spec）
- 不做详细的时序与状态流转（02-detail）
- 不评估工作量与排期
- 目标文件已存在时走"续做"分支，**不覆盖**
- **不假定非功能需求的量级**
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 非功能需求缺失（无性能/量级描述） | 记入待澄清清单，**不自行假定量级**——量级假设错误会导致架构整体返工 |
| 生效快照不存在 | 提示先运行 `ai-spec-build`，中止 |
| 架构与既有分层冲突 | 输出冲突点与两种方案的代价，交人决策，不自行取舍 |
| 需要引入规范包未覆盖的技术 | 停止并说明：新增技术栈需要先建规范包，否则后续无约束可依 |
