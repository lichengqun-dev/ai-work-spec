# 详细设计要点

> 本文件承载**「为什么」**：为什么标题必须带 FR 编号，以及异常分支为什么最容易写坏。
> 「做什么」在 `SKILL.md` 的执行步骤里，不重复。

## 为什么必须「每个 FR 一节，标题写成 `## FR-XXX-000 <功能名称>`」

这条不是排版要求，有三个具体原因：

1. **下游按编号读段落，不读全文。** 处理 `FR-CORE-045` 时只读该节，不读整份详细设计——否则上下文预算立刻爆掉
2. **gate-03 的 `fr-design-section` 检查项校验它。** FR 既不是标题也不带 `§` 引用时，该检查项报 WARN
3. **覆盖率可机械统计。** 标题形式是唯一能可靠解析出"哪些 FR 有设计"的形式

反例（都会导致上面三件事失效）：

```markdown
## 3.2 列表导出（FR-CORE-045）        ← 不是标题开头，解析不出
### 导出相关设计                       ← 标题里没有编号
### FR-CORE-045、FR-CORE-046 合并写       ← 一个成了、一个没成
```

正例：

```markdown
## FR-CORE-045 列表导出
```

## 异常分支为什么最容易"顺手编一个"

**异常分支是缺陷最集中的地方，也最容易"顺手编一个"。**

编出来的异常处理会被当成确定需求往下实现，而它与真实业务规则大概率不符——
这类错误到测试阶段才暴露，且很难判断是需求错了还是实现错了。
