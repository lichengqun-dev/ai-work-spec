# 能力声明

把 PRD 中的每个功能点展开成**功能详细设计**：时序、状态流转、异常分支、边界条件。

**每个 `FN` 独立一节，标题必须含 FN 编号。** 这不是排版偏好——下游要按编号读取相关段落而不是读整份文档（见 `00_工作空间配置/上下文注入规范.md` 的读取规则三），且 gate-03 会用 `fn-design-section` 校验这一点。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| PRD | `ai-requirement-04-prd` 产出 | 是 | 每个功能有 `FN` 编号 |
| 架构设计 | `ai-design-01-arch` 产出 | 是 | 含模块划分与依赖方向 |
| 需求问题汇总 | `ai-requirement-02-analysis` 产出 | 是 | 未解决项须原样带入 |
| 生效规范快照 | `.ai/spec-effective/<项目码>.md` | 是 | 分层约束从这里读 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 功能详细设计 | 项目文档仓 `docs/02_设计/功能详细设计.md` | **每 FN 一节，标题格式 `## FN-XXX-000 <名称>`** |
| 依赖关系回填 | `.ai/index/依赖关系图.md` | **从各 FN 时序中提取 FN 之间的依赖，追加登记** |

## 前置条件（不满足则拒绝执行）

- gate-03 尚未通过（已冻结则拒绝改写）
- 架构设计已产出
- PRD 中每个 `FN` 在功能详细设计中都有对应小节——**缺哪个不补哪个，不能整体放行**

## 执行步骤

1. 读 PRD，列出本批次全部 `FN`
2. **逐个 FN** 产出小节，标题为 `## <FN 编号> <功能名称>`
3. 每节写清：
   - 时序（调用链与关键交互）
   - 状态流转（有哪些状态、允许的迁移、禁止的迁移）
   - 异常分支（失败、无权限、状态冲突、并发冲突）
   - 边界条件（数据量、时间范围、上限）
4. 交叉校验：PRD 中的 FN 与本文件的章节一一对应，**多一个少一个都要报告**
5. 把 PRD 的未解决问题原样带入「待确认」小节
6. **回填依赖关系图**：从各 FN 的时序中提取「谁依赖谁」，按 `数据依赖` / `流程依赖` / `状态依赖` 追加登记
   （`ai-test-04-regression` 与 `ai-iteration-01-impact` 都以它为输入；
   此前它没有初始填充者——回填只发生在测试阶段，而迭代阶段在改动前就要用它）
7. 回写批次状态文件

## 边界（明确不做）

- **不设计表结构**（03-db）、**不定义接口契约**（04-api）——只在时序中提到"调用某某能力"，不写具体签名
- 不写代码、不给实现建议（用什么注解、什么工具类）
- 不改 PRD（发现 PRD 有问题应回到上游）
- **不解决待确认问题**，原样带入

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 某 FN 信息不足以写出时序 | 该节标注"信息不足"并列出缺什么，记入待澄清，**不编一套时序** |
| PRD 与本文件 FN 对不上 | 拒绝完成，列出差异（多余/缺失） |
| 异常分支写不出来 | 同上，记入待澄清——**异常分支是缺陷最集中的地方，编出来的异常处理比没有更危险** |
