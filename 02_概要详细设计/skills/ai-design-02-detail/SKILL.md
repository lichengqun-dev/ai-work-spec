# ai-design-02-detail · 功能详细设计

## 能力声明

把 PRD 中的每个功能点展开成**功能详细设计**：时序、状态流转、异常分支、边界条件。

**每个 `FR` 独立一节，标题必须含 FR 编号**（`## FR-XXX-000 <功能名称>`）。这不是排版偏好——
下游要按编号读取相关段落而不是读整份文档（见 `00_工作空间配置/上下文注入规范.md` 的读取规则三），
且 gate-03 会用 `fr-design-section` 校验这一点。三条具体原因与正反例见 `references/详细设计要点.md`。

**不设计表结构、不定义接口契约、不给实现建议**——见「边界」。

## 何时用 / 何时不用

- **用**：架构设计已产出，要把 PRD 的每个功能点展开成时序 / 状态流转 / 异常分支 / 边界条件时
- **不用**：只设计表结构（`ai-design-03-db`）；只定义接口契约（`ai-design-04-api`）；
  只规划页面与组件（`ai-design-05-frontend-spec`）

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| PRD | `ai-requirement-04-prd` 产出 | 是 | 每个功能有 `FR` 编号 |
| 架构设计 | `ai-design-01-arch` 产出 | 是 | 含模块划分与依赖方向 |
| 需求问题汇总 | `ai-requirement-02-analysis` 产出 | 是 | 未解决项须原样带入 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | 分层约束从这里读 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 功能详细设计 | 项目文档仓 `<需求名>/02_设计/功能详细设计.md` | **每 FR 一节，标题格式 `## FR-XXX-000 <名称>`** |
| 依赖关系回填 | `projects/<项目码>/.agent/index/依赖关系图.md` | **从各 FR 时序中提取 FR 之间的依赖，追加登记** |

产出结构——**每个 FR 一节，标题为 `## FR-XXX-000 <功能名称>`，每节写四件事**：

| 项 | 要求 | 写不出来时 |
|---|---|---|
| 时序 | 调用链与关键交互 | 标注"信息不足"，列出缺什么 |
| 状态流转 | 有哪些状态、允许/禁止的迁移 | — |
| 异常分支 | 失败、无权限、状态冲突、并发冲突 | **记入待澄清，不要编** |
| 边界条件 | 数据量上限、时间范围、并发量级 | 同上 |

## 前置条件

**hard（不满足则拒绝执行）**

- PRD 已产出（每个功能有 `FR` 编号）
- 架构设计已产出（含模块划分与依赖方向）
- 需求问题汇总已产出（未解决项须原样带入）
- 生效规范快照存在（分层约束从这里读）
- gate-03 尚未通过（**已冻结则拒绝改写**）

**soft**

- 无。上列各条都是硬依赖，没有"顺序性"前置——hard 全满足即可单独跑

## 执行步骤

1. 读 PRD，列出本批次全部 `FR`
2. **逐个 FR** 产出小节，标题为 `## <FR 编号> <功能名称>`
3. 每节按「产出契约」里的「每节写四件事」写全：时序、状态流转、异常分支、边界条件
4. **交叉校验（必须做）**：逐个对照 PRD——PRD 里的每个 FR 本文件有对应小节吗？本文件里有没有 PRD 中
   不存在的 FR？**两边对不上就拒绝完成**，列出差异。多出来的 FR 往往意味着凭空造了需求；少了的意味着漏了设计
5. 把 PRD 的「待确认事项」节**原样复制**到本文件的同一节，不要删、不要自行回答
6. **回填依赖关系图**：从各 FR 的时序中提取「谁依赖谁」，按 `数据依赖` / `流程依赖` / `状态依赖` 追加登记
   （`ai-test-04-regression` 与 `ai-iteration-01-impact` 都以它为输入；
   此前它没有初始填充者——回填只发生在测试阶段，而迭代阶段在改动前就要用它）
7. 回写批次状态文件：本步骤置 `done`，在 `artifacts` 登记 `<需求名>/02_设计/功能详细设计.md` 与哈希

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始
- 本 Skill 无 soft 前置，因此不存在"未经上游确认"的标注场景
- 批次状态文件不可写（如未接入批次）时：产出物落到指定路径，跳过状态回写并在报告中说明

## 边界（明确不做）

- **不设计表结构**（03-db）、**不定义接口契约**（04-api）——只在时序中提到"调用某某能力"，
  不写具体签名（如 `orderMapper.selectByCondition(req)`）
- **不给实现建议**（用什么注解、哪个工具类）。技术细节在生效规范快照里，不在这里
- 不改 PRD（发现 PRD 有问题应回到上游）
- **不解决待确认问题**，原样带入
- 不合并多个 FR 进一节；不在标题里省略编号（写成 `## 列表导出` 是不行的）
- 不要为了"看起来完整"而补全异常分支与边界
- 不写代码
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 某 FR 信息不足以写出时序 | 该节标注"信息不足"并列出缺什么，记入待澄清，**不编一套时序** |
| PRD 与本文件 FR 对不上 | 拒绝完成，列出差异（多余/缺失） |
| 异常分支写不出来 | 同上，记入待澄清——**异常分支是缺陷最集中的地方，编出来的异常处理比没有更危险** |
