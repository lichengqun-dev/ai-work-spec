# ai-design-03-db · 数据库设计

## 能力声明

依据功能详细设计产出**数据库设计**：表结构、字段、索引、DDL 与**回滚脚本**。

**回滚脚本与 DDL 一起产出，不是可选项。** 上线出问题时没有时间现场推导回滚语句（符合 `STD-BASE-311`）。

**不做什么**：不写查询逻辑（Mapper / SQL）、不执行数据迁移、不做性能调优——见「边界」。

## 何时用 / 何时不用

- **用**：功能详细设计已产出，要把设计落到表结构、字段、索引时（含为已有表加列 / 加索引）
- **不用**：只是写查询 SQL（编码阶段的事）；只改一处字段注释（走快车道）
- **涉及已有表的破坏性变更**：仍走本 Skill，但必须走变更子批次（见「前置条件」）

`applicable_stacks: [db-dm8, db-gaussdb]`：本 Skill 只在**已建了 `db-*` 规范包的数据库**下可用。
**具体用哪个包由生效快照的 C 段决定，不要假定默认值**——两个包的规则有多条**方向相反**
（标识符大小写查找、空串与 NULL 是否等价、`FROM DUAL`、`CONCAT` 参数个数），套错会写出
**语法正确但语义错误**的 SQL。换数据库需新建 `db-*` 规范包并改此处声明。

## 前置条件

**hard（不满足则拒绝执行）**

- 功能详细设计已产出（每 FR 一节）
- 生效快照中 `db` 维度的规范包存在（无则拒绝——**没有方言约束就写 DDL，等于裸奔**）
- 涉及已有表的变更时，**已存在对应的变更子批次**（`STD-BASE-601`）——不得直接改写已归档的设计

**soft（不满足则提示，可继续）**

- 架构设计已产出（缺则模块划分可能与其他设计不一致，产出物标注）
- gate-03 设计评审已通过（未通过时产出物标注"未经评审"）

## 执行步骤

1. 从功能详细设计的时序中提取**数据实体**与关系
2. 设计表结构：表名遵循 `TBL_<模块码>_<表名>`，字段类型按 `db-*` 包的方言规范选
3. **每个字段写注释**；枚举型字段写明取值含义（符合 `STD-BASE-312`）
4. 为高频查询条件设计索引，并说明索引覆盖的是哪个查询
5. 产出 DDL 与**回滚脚本**（成对）
6. 标注迁移顺序（多表变更时的执行次序）
7. 回写批次状态文件：本步骤置 `done`，登记 `<需求名>/02_设计/数据库设计.md` 与哈希

### 两份硬性要求

**要求一：每个字段必须有注释，枚举型写明取值。**
gate-03 的 `db-field-comments` 会校验（WARN）。这不是格式洁癖——字段含义只存在于开发者记忆中时，
人一换就成了不可知数据；而且注释是 AI 生成代码与 SQL 时最关键的上下文来源。

**要求二：DDL 与回滚脚本成对产出。**
gate-03 的 `ddl-rollback` 是 **BLOCK** 级：有 DDL 但没回滚方案，门禁不通过。

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始
- soft 不满足时照常产出，并在产出物顶部标注「未经上游确认 —— <哪一条没满足>」
- 状态文件不可写（如未接入批次）时：产出物落到指定路径，跳过状态回写并在报告中说明

## 边界（明确不做）

- **不写查询逻辑**（Mapper 方法、SQL 语句）——那是编码阶段的事
- 不改已归档批次的表结构，走变更子批次
- 不做数据迁移脚本的执行（只产出脚本）
- 不做性能调优（索引设计是设计，压测是另一回事）
- **不要为了通过门禁而补一个假的回滚脚本**
- 不要在有破坏性变更（删列、改类型、加非空列）时默默继续

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 字段含义无法确定 | 标注"待确认"并记入待澄清，**不猜字段含义**——字段注释只存在于开发者记忆中时，人一换就成了不可知数据 |
| 快照中无 `db` 规范包 | 拒绝执行，提示先建或补规范包 |
| DDL 涉及已有表的破坏性变更（删列改类型） | 停止，输出影响面与迁移方案，交人决策 |
| 回滚脚本无法写出（如删列后数据不可恢复） | 明确标注"不可逆变更"并说明后果，交人确认后才能继续 |
| 涉及已有表却没有变更子批次 | 拒绝执行，先走变更子批次（`STD-BASE-601`） |
