# 能力声明

依据功能详细设计产出**数据库设计**：表结构、字段、索引、DDL 与**回滚脚本**。

**回滚脚本与 DDL 一起产出，不是可选项。** 上线出问题时没有时间现场推导回滚语句（符合 `STD-BASE-311`）。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 功能详细设计 | `ai-design-02-detail` 产出 | 是 | 每 FN 一节 |
| 架构设计 | `ai-design-01-arch` 产出 | 是 | 模块划分 |
| 领域模型 | `09_资产库/领域模型/` | 否 | 存在则复用既有实体定义 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | **数据库方言与设计规范从这里读** |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 数据库设计 | 项目文档仓 `<需求名>/02_设计/数据库设计.md` | DDL + 字段注释 + 索引说明 + **回滚脚本** |

`applicable_stacks: [db-dm8]`：本 Skill 只在达梦 DM8 项目下可用。换数据库需新建 `db-*` 规范包并改此处声明。

## 前置条件（不满足则拒绝执行）

- 功能详细设计已产出
- 生效快照中 `db` 维度的规范包存在（无则拒绝——**没有方言约束就写 DDL，等于裸奔**）
- 涉及已有表的变更 → **必须走变更子批次**（`STD-BASE-601`），不得直接改写已归档的设计

## 执行步骤

1. 从功能详细设计的时序中提取**数据实体**与关系
2. 设计表结构：表名遵循 `TBL_<模块码>_<表名>`，字段类型按 `db-*` 包的方言规范选
3. **每个字段写注释**；枚举型字段写明取值含义（符合 `STD-BASE-312`）
4. 为高频查询条件设计索引，并说明索引覆盖的是哪个查询
5. 产出 DDL 与**回滚脚本**（成对）
6. 标注迁移顺序（多表变更时的执行次序）
7. 回写批次状态文件

## 边界（明确不做）

- **不写查询逻辑**（Mapper 方法、SQL 语句）——那是编码阶段的事
- 不改已归档批次的表结构，走变更子批次
- 不做数据迁移脚本的执行（只产出脚本）
- 不做性能调优（索引设计是设计，压测是另一回事）

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 字段含义无法确定 | 标注"待确认"并记入待澄清，**不猜字段含义**——字段注释只存在于开发者记忆中时，人一换就成了不可知数据 |
| 快照中无 `db` 规范包 | 拒绝执行，提示先建或补规范包 |
| DDL 涉及已有表的破坏性变更（删列改类型） | 停止，输出影响面与迁移方案，交人决策 |
| 回滚脚本无法写出（如删列后数据不可恢复） | 明确标注"不可逆变更"并说明后果，交人确认后才能继续 |
