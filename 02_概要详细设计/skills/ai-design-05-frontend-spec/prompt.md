# 指令：前端页面 / 组件 / 状态设计

## 开始前

遍历原型工程（读 `data-fn` 标记）、功能详细设计、已冻结的接口契约、组件清单。

**没有原型就不要开始。** 前端设计必须基于业务方已确认的原型——凭空设计会做出没人确认过的界面，
而这类返工通常到 UI 走查甚至上线后才暴露。

## 产出结构

```markdown
# 前端设计

## 一、页面清单
| PAGE 编号 | 页面 | 路由 | 对应 FN | 原型页面 |

## 二、组件拆分
| 组件 | 复用/新建 | 来源 | 职责 |
| 数据表格 | 复用 | fe-vue3-elementplus 包的通用表格 | 列表展示 |

## 三、状态流转
| 状态 | 归属 | 说明 |
| 列表数据 | 服务端状态 | 由 useExportList() 管理，组件卸载即释放 |
| 筛选条件 | 客户端状态（页面级） | 表单草稿 |

## 四、接口调用映射
| 页面 | 交互 | 调用接口 | 对应 FN |

## 五、异常态与空态
| 页面 | 无数据 | 无权限 | 加载失败 |
```

## 最容易出错的一步：状态归属

**不要顺手把接口数据放进全局 store。** 判定表：

| 状态类型 | 归属 | 判据 |
|---|---|---|
| 接口返回的数据 | 请求层（hook / service） | 它有没有"一份还是多份"的问题？有就是服务端状态 |
| 跨页面共享的 UI 状态 | 全局 store | 多个页面要读同一份 |
| 单页面的 UI 开关、tab、表单草稿 | 组件本地 | 离开页面就该丢 |

服务端状态进全局 store 后，缓存失效、竞态、重复请求全要手工处理，而且容易出现
"两个页面看到同一份过期数据"——这类问题在测试阶段极难复现。

## 组件拆分：能复用的一律复用

查 `09_资产库/组件库/前端组件清单.md`。**新组件要写明拆出的理由**，否则很容易出现
"同一个表格在五个页面各写了一遍，每一遍的处理方式都稍有不同"。

前面 `ai-requirement-03-prototype` 已经做过一次"先匹配已有组件"，
这里是第二次——原型里的复用是概念层面，这里的复用要落到具体组件。

## 接口调用映射用来发现孤儿

建完映射后**反向检查**：契约里的每个 operation，有没有被任何页面的任何交互调用？

没有调用方的接口通常意味着**有需求没被设计覆盖**。也可能只是设计时多加了接口。
两种都该列出来让人确认。

## 异常态与空态必须写全

原型阶段 gate-02 已经要求过"异常态与空态有呈现"（WARN），这里是把它落到具体呈现方式：

- 无数据：显示空状态还是空表格？
- 无权限：隐藏入口还是显示 403 页面？
- 加载失败：重试按钮 + 错误提示，还是自动重试？

**写不出来就记入待澄清。** 异常态在实现阶段随手写的结果，通常三个页面三种做法。

## 你绝对不要做的事

- 不要写前端代码（那是 `ai-dev-03-frontend`）
- 不要做视觉设计（配色、图标、动效）
- 不要在没有原型时凭描述设计页面
- 不要修改原型
- 不要执行 git 操作
