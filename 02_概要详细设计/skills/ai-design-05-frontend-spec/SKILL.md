# ai-design-05-frontend-spec · 前端设计

## 能力声明

依据原型工程、功能详细设计与接口契约产出**前端设计**：页面结构、组件拆分、状态流转、接口调用映射。

**前端设计是原型到工程实现的桥。** 原型验证的是"信息结构与交互路径对不对"，
前端设计要回答的是"这些页面在工程里怎么组织"。

**不做什么**：不写前端代码、不做视觉设计、不改原型、不重新定义接口——见「边界」。

## 何时用 / 何时不用

- **用**：原型工程、功能详细设计、接口契约都已就位，要把原型落到页面/组件/状态/接口映射时
- **不用**：只是写前端代码（`ai-dev-03-frontend`）；只是调配色与动效（本 Skill 不做视觉设计）；
  原型本身要改（回到 `ai-requirement-03-prototype`）
- **没有原型时不要开始**：前端设计必须基于业务方已确认的原型——凭空设计会做出没人确认过的界面，
  而这类返工通常到 UI 走查甚至上线后才暴露

## 前置条件

**hard（不满足则拒绝执行）**

- 原型工程可访问（**无原型则拒绝**——前端设计必须基于已确认的原型）
- 功能详细设计与接口契约均已产出
- 生效快照中 `fe` 维度的规范包存在

**soft**

- 无。上列各条都是硬依赖，没有"顺序性"前置——hard 全满足即可单独跑

## 执行步骤

1. 遍历原型页面，提取 `data-fn` 标记，建立「原型元素 → FN」映射
2. 规划页面与路由，申请 `PAGE-<模块码>-<3位>` 编号
3. **组件拆分**：查 `09_资产库/组件库/前端组件清单.md`，**能复用的一律复用**；新组件写明拆出的理由。
   （`ai-requirement-03-prototype` 已经做过一次"先匹配已有组件"，这里是第二次——原型里的复用是概念层面，
   这里的复用要落到具体组件）
4. 标注**状态归属**：哪些是服务端状态（接口数据）、哪些是客户端状态（UI 开关、表单草稿）
5. 建立**接口调用映射**：哪个页面的哪个交互调用哪个 `API` 编号
6. 标注异常态与空态的呈现方式（无数据、无权限、加载失败）
7. 回写批次状态文件：本步骤置 `done`，登记 `<需求名>/02_设计/前端设计.md` 与哈希、`PAGE` 编号清单

### 状态归属的判定

**不要顺手把接口数据放进全局 store。** 判据：

| 状态 | 归属 | 判据 |
|---|---|---|
| 接口返回的数据 | 请求层（hook / service），不进全局 store | 它有没有"一份还是多份"的问题？有就是服务端状态 |
| 跨页面共享的 UI 状态 | 全局 store | 多个页面要读同一份 |
| 单页面内的 UI 开关、tab 选中、表单草稿 | 组件本地 | 离开页面就该丢 |

服务端状态进全局 store 后，缓存失效、竞态、重复请求都要手工处理，且容易出现"两个页面看到同一份过期数据"——
这类问题在测试阶段极难复现。

### 接口调用映射要反向检查孤儿

建完映射后**反向检查**：契约里的每个 operation，有没有被任何页面的任何交互调用？

没有调用方的接口通常意味着**有需求没被设计覆盖**，也可能只是设计时多加了接口。两种都该列出来让人确认。

### 异常态与空态必须写全

原型阶段 gate-02 已经要求过"异常态与空态有呈现"（WARN），这里是把它落到具体呈现方式：

- 无数据：显示空状态还是空表格？
- 无权限：隐藏入口还是显示 403 页面？
- 加载失败：重试按钮 + 错误提示，还是自动重试？

**写不出来就记入待澄清。** 异常态在实现阶段随手写的结果，通常三个页面三种做法。

## 独立执行

- **hard 全满足即可单独运行**，不必从流程第一步开始（如只补一条接口到页面的映射）
- 本 Skill 无 soft 前置，因此不存在"未经上游确认"的标注场景
- 批次状态文件不可写（如未接入批次）时：产出物落到指定路径，跳过状态回写并在报告中说明

## 边界（明确不做）

- **不写前端代码**（那是 `ai-dev-03-frontend`）
- **不做视觉设计**（配色、图标、动效）——原型验证的是结构与交互，前端设计延续这个边界
- 不改原型（发现原型有问题应回到 `ai-requirement-03-prototype`）
- 不定义接口（契约已冻结）
- 不在没有原型时凭描述设计页面
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 原型中 `data-fn` 标记缺失 | 列出缺失清单并**拒绝完成**——缺少标记就无法建立页面与 FN 的映射，前端设计会退化成凭印象画界面 |
| 某接口无人调用 | 列出——**孤儿接口通常意味着有需求没被设计覆盖** |
| 前端规范包缺失 | 提示先建或补规范包，中止 |
| 异常态 / 空态写不出来 | 记入待澄清，**不随手写一个**——随手写的结果通常三个页面三种做法 |
