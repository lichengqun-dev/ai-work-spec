# 能力声明

依据原型工程、功能详细设计与接口契约产出**前端设计**：页面结构、组件拆分、状态流转、接口调用映射。

**前端设计是原型到工程实现的桥。** 原型验证的是"信息结构与交互路径对不对"，前端设计要回答的是"这些页面在工程里怎么组织"。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 原型工程 | `ai-requirement-03-prototype` 产出 | 是 | 页面元素带 `data-fn` 标记 |
| 功能详细设计 | `ai-design-02-detail` 产出 | 是 | 每 FN 一节 |
| 接口契约 | `ai-design-04-api` 产出 | 是 | 每个 operation 带 `x-fn-id` |
| 前端组件清单 | `09_资产库/组件库/前端组件清单.md` | 否 | 存在则优先复用 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | 前端技术栈与工程规范从这里读 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 前端设计 | 项目文档仓 `<需求名>/02_设计/前端设计.md` | 含页面清单（`PAGE-<模块码>-<3位>`）、组件拆分、状态流转、接口映射 |

## 前置条件（不满足则拒绝执行）

- 功能详细设计与接口契约均已产出
- 原型工程可访问（**无原型则拒绝**——前端设计必须基于已确认的原型，凭空设计会做出业务方没确认过的界面）
- 生效快照中 `fe` 维度的规范包存在

## 执行步骤

1. 遍历原型页面，提取 `data-fn` 标记，建立「原型元素 → FN」映射
2. 规划页面与路由，申请 `PAGE-<模块码>-<3位>` 编号
3. **组件拆分**：查组件清单，能复用的一律复用；新组件写明拆出的理由
4. 标注**状态流转**：哪些是服务端状态（接口数据）、哪些是客户端状态（UI 开关、表单草稿）
5. 建立**接口调用映射**：哪个页面的哪个交互调用哪个 `API` 编号
6. 标注异常态与空态的呈现方式（无数据、无权限、加载失败）
7. 回写批次状态文件

## 边界（明确不做）

- **不写前端代码**（那是 `ai-dev-03-frontend`）
- **不做视觉设计**（配色、图标、动效）——原型验证的是结构与交互，前端设计延续这个边界
- 不改原型（发现原型有问题应回到 `ai-requirement-03-prototype`）
- 不定义接口（契约已冻结）

## 状态归属的判定

这一步最容易出错的是**把服务端状态塞进全局 store**。判据：

| 状态 | 归属 |
|---|---|
| 接口返回的数据 | 请求层管理，不进全局 store |
| 跨页面共享的 UI 状态 | 全局 store |
| 单页面内的 UI 开关、tab 选中 | 组件本地 |

服务端状态进全局 store 后，缓存失效、竞态、重复请求都要手工处理，且容易出现"两个页面看到同一份过期数据"。

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 原型中 `data-fn` 标记缺失 | 列出缺失清单并**拒绝完成**——缺少标记就无法建立页面与 FN 的映射，前端设计会退化成凭印象画界面 |
| 某接口无人调用 | 列出——**孤儿接口通常意味着有需求没被设计覆盖** |
| 前端规范包缺失 | 提示先建或补规范包，中止 |
