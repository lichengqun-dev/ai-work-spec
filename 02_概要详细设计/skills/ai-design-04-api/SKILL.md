# 能力声明

依据功能详细设计与数据库设计产出**接口契约（OpenAPI）**，并在 gate-03 通过后进入冻结态。

**契约是前后端并行开发的唯一依据。** 契约不冻结，并行开发必然在联调时返工——而联调返工是代价最高的一类返工，因为它同时占用前后端两个人的时间。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 功能详细设计 | `ai-design-02-detail` 产出 | 是 | 每 FN 一节 |
| 数据库设计 | `ai-design-03-db` 产出 | 是 | 字段类型须与契约一致 |
| 需求功能分析 | `ai-requirement-02-analysis` 产出 | 是 | 用于申请 `API` 编号 |
| 生效规范快照 | `.ai/spec-effective/<项目码>.md` | 是 | 接口设计规范（`STD-BASE-32x`）从这里读 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 接口契约 | 项目文档仓 `docs/02_设计/接口契约.yaml` | OpenAPI 3，**每个 operation 带 `x-fn-id` 与 4xx/5xx 响应** |
| 接口登记 | `.ai/index/功能编号总表.md` 接口段 | `API-<模块码>-<3位>` + 所属 FN + 契约版本 |

## 前置条件（不满足则拒绝执行）

- 数据库设计已产出
- 契约尚未冻结（已冻结则拒绝改写——**冻结后变更必须走变更子批次**）
- 功能详细设计中涉及外部交互的 FN 全部已列出（漏一个就等于漏一个接口）

## 执行步骤

1. 从功能详细设计的时序中提取**接口边界**（哪些调用跨进程/跨前后端）
2. 向编号总表申请 `API-<模块码>-<3位>` 编号
3. 逐个产出 operation，**必须包含**：
   - `x-fn-id`: 该接口服务的 `FN` 编号（gate-03 的 `api-has-fn` 校验）
   - `responses` 中至少一个 4xx/5xx（gate-03 的 `api-error-codes` 校验）
   - 完整的请求/响应 schema，字段类型与数据库设计一致
4. 校验契约结构（gate-03 的 `openapi-valid` 校验）
5. 登记接口到编号总表
6. 回写批次状态文件

## 边界（明确不做）

- **不实现接口**（那是编码阶段的事）
- 不做接口性能设计（压测是另一回事）
- 不定义内部方法签名——契约只描述**跨边界**的调用
- **冻结后不修改**。变更走变更子批次并通知前后端负责人

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 某接口无法追溯到 FN | 拒绝完成并列出——**孤儿接口往往意味着需求分析漏了东西，或设计时凭空加了一个** |
| 字段类型与数据库设计冲突 | 以数据库设计为准并报告冲突，不自行取舍 |
| 契约无法通过结构校验 | 修正后重跑，不降低校验标准 |
| 已冻结契约需变更 | 停止，说明需开变更子批次（`<原批次号>-C<n>`） |

## 契约冻结

契约在本 Skill 产出，在 **gate-03 通过后**进入冻结态。冻结动作由 `ai-design-06-review` 在门禁通过后记录。

冻结的语义是：**此后任何变更都需要通知前后端双方，并重跑受影响的下游步骤。**

## 与其他 Skill 的关系

- 上游：`ai-design-02-detail`、`ai-design-03-db`
- 下游：`ai-dev-02-backend`、`ai-dev-03-frontend`、`ai-test-02-automation`
- 门禁：`api-has-fn`（BLOCK）、`api-error-codes`（WARN）、`openapi-valid`（BLOCK）
