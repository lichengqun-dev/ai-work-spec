# 能力声明

产出**发布说明**与**上线步骤（含回滚方案）**，并对齐版本号。

**回滚方案与上线步骤一同产出，不是可选项。** gate-05 的 `rollout-plan-present` 是 BLOCK 级检查项。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 测试报告 | `ai-test-05-report` 产出 | 是 | 含上线建议 |
| 变更登记 | `ai-iteration-03-change-control` 产出 | 是（迭代路径） | 含变更项与基线 |
| 数据库设计 | 本批次产出物 | 否 | 含 DDL 与回滚脚本时用于组织上线顺序 |

**注意：本 Skill 不依赖 `ai-archive-01-close`。** 归档在本流程里是**本 Skill 之后**的一步
（第 23 步 vs 第 22 步），把它当上游会形成环。FN 清单从 `projects/<项目码>/.agent/index/功能编号总表.md` 读即可。

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 上线步骤 | 项目文档仓 `<需求名>/05_交付/上线步骤.md` | 步骤 + **回滚方案** |
| 发布说明 | 项目文档仓 `<需求名>/05_交付/发布说明.md` | 面向使用方的变更说明 |
| 版本号 | 项目代码仓 | 按项目版本约定更新 |

## 前置条件（不满足则拒绝执行）

- 测试报告已产出，且上线建议不是"不建议上线"
- 有 DDL 变更时，其回滚脚本已存在（`ai-design-03-db` 产出）

**这里刻意*不*要求「gate-05 已通过」。** 本 Skill 的产出正是 gate-05 第 4 项
`rollout-plan-present`（BLOCK）的校验对象——要求 gate-05 先通过会形成死锁：
门禁要的文件，只有"门禁已通过"才能产出。

「不带着未关闭的 P0/P1 上线」这条约束**由 gate-05 在本 Skill 之后强制执行**，不靠前置条件。
顺序是：`test-report` → **`release`（产出方案）** → **gate-05（校验方案 + 测试结论）** → 真正上线 → `archive`。

## 执行步骤

1. 读测试报告的上线建议与遗留风险，**原样带入发布说明**（不美化）
2. 组织上线步骤，按依赖排序：
   - DDL 与数据迁移在前，服务发布在后
   - 多个服务时标注发布顺序
   - 标注**不可逆步骤**（如删列、数据清洗）
3. 产出回滚方案：对应每一步的反向操作
4. 产出发布说明：面向使用方的变更描述（做了什么、有什么影响、需要注意什么）
5. 版本号按项目约定更新
6. 回写批次状态文件

## 边界（明确不做）

- **不执行部署**。只产出方案，执行是运维/发布的职责
- 不修改缺陷状态（那是 `ai-test-03-execute`）
- 不美化遗留风险（测试报告里写了什么就带什么）
- 不做上线后的验证（那是回归验证，属 `ai-test-03-execute`）

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 测试报告缺失 | **拒绝执行**，提示先跑 `ai-test-05-report` |
| 存在不可逆步骤 | 明确标注「不可逆」并说明后果，**不写假的反向操作** |
| DDL 缺回滚脚本 | 拒绝执行，回到 `ai-design-03-db` 补齐 |
| 测试报告建议"不建议上线" | 拒绝组织上线，输出报告中列出的未关闭项 |
| 多服务发布顺序不明确 | 停下询问，**不自行假定顺序** |

## 不可逆步骤怎么处理

| 变更 | 能否回滚 |
|---|---|
| 建表 / 加列 / 加索引 | 能 |
| 删列 / 改类型（缩小精度） | **不能** |
| 数据清洗（覆盖原值） | **不能**（除非先备份） |

不可逆步骤的处理方式：

1. **前置备份**：能备份的先备份，并把备份与恢复方式写进方案
2. **明确标注**：在步骤里标「不可逆」，说明"执行后 X 不可恢复"
3. ****不写假的反向 SQL**：写一句 `-- 反向：无` 比写一句看起来能回滚实则无效的 SQL 安全得多

**一个假装可回滚的方案，比明说"这一步回不去"危险得多**——前者会让人在有退路的心态下执行不可逆操作。

## 发布说明的读者是使用方，不是开发者

| 内容 | 该不该写 |
|---|---|
| 新增了什么能力、怎么用 | ✅ |
| 行为有什么变化（含兼容性影响） | ✅ |
| 需要注意什么（限制、暂不支持） | ✅ |
| 内部重构、性能优化细节 | ❌（除非有外部可感知的影响） |
| 遗留风险 | ✅（**必须写，且不弱化**） |

## 与其他 Skill 的关系

- 上游：`ai-test-05-report`（必备）、`ai-iteration-03-change-control`（迭代路径）
- **下游不是归档，而是门禁**：本 Skill 产出 gate-05 要校验的上线方案（`rollout-plan-present`，BLOCK）。
  归档（`ai-archive-01-close`）在 gate-05 通过、真正上线之后
- 再下游：执行部署（人工 / 运维）→ `ai-archive-01-close`
- 门禁：`rollout-plan-present`（BLOCK，按「交付」路径产出物 + 回滚方案解析）
