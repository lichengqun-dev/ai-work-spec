# 指令：发布说明与上线步骤

## 开始前先确认

**测试报告已产出，且上线建议不是「不建议上线」。** 缺报告就停下，提示先跑 `ai-test-05-report`。

**注意本 Skill 跑在 gate-05 *之前*，不是之后。** 你的产出正是 gate-05 要校验的上线方案——
要求 gate-05 先通过会形成死锁。所以：

- 你**只负责把方案写出来**，不负责判断"能不能上线"
- 「不带着未关闭的 P0/P1 上线」由 **gate-05 在你之后**强制执行。你不用去查缺陷状态
- 但方案里**要如实带入**遗留风险（从测试报告原样抄，不美化），那是 gate-05 与使用方判断的依据

读测试报告的上线建议与遗留风险。**它们要原样带进发布说明，不美化。**

## 产出物必须落在「交付」路径下

gate-05 的 `rollout-plan-present` 是 BLOCK 级，它按路径关键词找交付类产出物：

```
<需求名>/05_交付/上线步骤.md      ← 路径含「交付」，可被检出
<需求名>/05_交付/发布说明.md
```

放在别的目录（如 `<需求名>/04_测试/`）会让检查项报"没有交付类产出物"。
**那个告警是对的**——上线方案放在测试目录下，发布时没人会去那里找。

## 上线步骤：按依赖排序

```markdown
# 上线步骤

## 一、前置检查
- [ ] 数据库备份已完成
- [ ] 回滚脚本已验证可用

## 二、执行步骤

| # | 步骤 | 执行人 | 预计耗时 | 可逆 |
|---|---|---|---|---|
| 1 | 执行 DDL（TBL_APP_EXPORT 建表） | DBA | 1 min | 是 |
| 2 | 发布后端服务 v1.2.0 | 运维 | 5 min | 是 |
| 3 | 发布前端资源 v1.2.0 | 运维 | 3 min | 是 |
| 4 | 执行数据清洗脚本 | DBA | 10 min | **否** |

## 三、回滚方案
| 步骤 | 回滚操作 | 耗时 | 备注 |
|---|---|---|---|
| 1 | DROP TABLE TBL_APP_EXPORT | 1 min | — |
| 2 | 回滚到 v1.1.9 | 5 min | — |
| 3 | 回滚前端资源 | 3 min | — |
| 4 | **无** | — | 数据已被覆盖，需从步骤 0 的备份恢复 |
```

## 不可逆步骤：标注，不要假装能回滚

| 变更 | 能回滚吗 |
|---|---|
| 建表 / 加列 / 加索引 | 能 |
| **删列 / 改类型（缩小精度）** | **不能** |
| **数据清洗（覆盖原值）** | **不能**（除非先备份） |

处理方式，按优先级：

1. **前置备份**——能备份的先备份，并把恢复步骤写进方案
2. **明确标注**——在表格的「可逆」列标"否"，并说明"执行后 X 不可恢复"
3. **写 `无`，不要写假的反向 SQL**

**第三点很重要。** 写一句 `-- 反向：ALTER TABLE ... ` 看起来能回滚、实则无效，
会让人在有退路的心态下执行不可逆操作。**一个假装可回滚的方案比明说"回不去"危险得多。**

## 发布说明：读者是使用方

```markdown
# 发布说明 v1.2.0

## 新增
- 列表页支持按分组维度导出

## 行为变化
- 导出结果新增「分组」列（**兼容性影响**：依赖固定列序的下游脚本需调整）

## 注意事项
- 单次导出上限 1 万条（超出会分片下载）

## 已知限制
- 3 条用例因第三方沙箱不可用未执行，恢复后 24 小时内补测
- P2 缺陷 1 条转入下批次：导出文件名为英文
```

| 该写 | 不该写 |
|---|---|
| 新增能力、怎么用 | 内部重构细节 |
| 行为变化（含兼容性影响） | 纯技术优化（除非外部可感知） |
| 注意事项（限制、暂不支持） | 缺陷编号等内部信息 |
| **遗留风险（不弱化）** | — |

**遗留风险必须写，且不弱化。** 发布说明是使用方唯一的知情渠道，
把风险藏着，等于让他们在不知情的情况下承担后果。

## 多服务发布顺序不明确时

**停下问用户**，不要假定顺序。

发布顺序错了会导致：新版本服务调用旧版本服务，接口不兼容——而这类问题在灰度阶段不一定暴露，
全量后才出现。

## 完成后

回写批次状态文件：本步骤置 `done`，登记上线步骤、发布说明与哈希。

## 你绝对不要做的事

- 不要**自己去判断**能不能上线——那是 gate-05 的事，你只把方案写出来
- 不要把上线方案放在非「交付」路径下
- **不要为不可逆步骤写假的反向 SQL**
- 不要在发布说明里省略或弱化遗留风险
- 不要自行假定多服务的发布顺序
- 不要执行部署
- 不要执行 git 操作
