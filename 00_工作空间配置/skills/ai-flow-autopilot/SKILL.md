# 能力声明

**研发流程的总入口。** 接收一句话描述，判定路径，驱动全流程，每阶段自动跑门禁。

它是**编排层**：不做任何实际工作，只负责判定、调用、拦截、状态推进。

## 为什么需要它

没有它时，使用者必须知道：40 个 Skill 各自的职责、四条路径的区别、每一步对应哪个 Skill、
什么时候该跑哪道门禁。**这是"上手难度高"的全部来源。**

有了它，使用者只说一件事：「给列表页加个导出」。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 任务描述 | 用户 | 是 | 能判断出「做什么 + 对哪个项目」。判断不了则澄清，**不猜** |
| 项目码 | 用户，或从描述推断 | 是 | `projects/<项目码>/` 存在 |
| 生效规范快照 | `projects/<项目码>/.agent/spec-effective/<项目码>.md` | 是 | 不存在则先运行 `ai-spec-build` |
| 全部下游 Skill | 各域 `skills/` | 是 | 每个都有 `SKILL.md` 且前置条件可判定 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 路径判定结论 | 输出给用户 | 路径类型 + 依据 + 下一步 |
| 批次状态 | `projects/<项目码>/.agent/state/<批次号>.yaml` | 各步骤状态与门禁结果齐全 |
| 全部下游产出物 | 见各 Skill 的产出契约 | — |

## 前置条件（不满足则拒绝执行）

- 目标项目已接入（`projects/<项目码>/.agent/project.yaml` 存在且 `repo` 字段已填真实路径）
- 生效规范快照存在（无快照则先运行 `ai-spec-build`，**不要在规范未知的情况下开工**）
- 当前无同项目的 `in_progress` 批次（有则先续做或关闭，**不允许并行两个批次**）

## 执行步骤

```
1. 判定项目码 —— 判断不了就问，不猜

2. 判定路径（依据见 references/路径判定.md）
   ├─ 新建（new）    从零到一的新系统          → 全部 23 步
   ├─ 迭代（change） 已有系统加功能 / 改行为   → ai-iteration-01-impact 起
   ├─ 快车道         小改动（量化准入条件）    → ai-daily-01-fastlane
   └─ 咨询           只是问问题                → ai-daily-04-qa（只读，不建批次）

3. 驱动
   每步：读该 Skill 的 SKILL.md 核对前置条件 → 不满足则停下说明 → 满足则按 prompt.md 执行
        → 产出物登记到 artifacts → 该阶段结束时跑对应门禁
   门禁：failed → 停下报明细；pending_manual → 列出人工清单等待签核；通过 → 继续

4. 收尾
   归档走 ai-archive-01-close；输出本批次做了什么、有哪些遗留
```

## 边界（明确不做）

- **不做实际工作。** 一切由被编排的 Skill 完成
- **不代替人做判断**：门禁的人工项、需求取舍、架构选型、验收签字，全部交还给人
- **不替用户决定路径**。判定有歧义时问，不要选一个默认值继续
- 不跳过任何步骤，即使觉得"这一步没必要"
- 不自动豁免、不自动续期
- 不调用 `status: not_implemented` 的 Skill（本仓库目前无此类）
- 不执行 git 操作

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 任务描述判断不出项目 | 澄清，中止 |
| 路径判定有歧义 | 列出两种可能及各自代价，请用户确认 |
| 某 Skill 拒绝执行（前置条件不满足） | 停止，报告是哪一条不满足、需要先做什么 |
| 门禁 `failed` | 停止，原样输出未通过项与定位；**不尝试绕过** |
| 门禁 `pending_manual` | 列出人工清单，等 `--confirm --by <名字>`；**不替人签核** |
| 门禁遇 BLOCK 级 skip | 说明需补齐材料或走 `--waive`（带批准人与复查期） |
| 批次中断（超上下文 / 人下班） | 状态文件已记录进度，下次从 `current_step` 续做 |

## 与其他 Skill 的关系

- 下游：**全部阶段 Skill**（它按路径选择性调用，不含 `ai-spec-*` 那四个治理工具）
- 专项编排：`ai-requirement-autopilot` 只编排需求段（01 域内部），本 Skill 编排全流程
- 依赖：`ai-gate-runner`（每阶段门禁）、`ai-spec-build`（规范快照）
