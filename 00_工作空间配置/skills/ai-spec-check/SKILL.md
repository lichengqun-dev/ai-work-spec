# 能力声明

对全库做**跨文件一致性检查**，输出问题清单。

它查的不是"某个文件写错了"，而是**单看每个文件都没问题、拼起来才暴露**的那类问题：
编号被引用却没有定义、Skill 名拼错、三件套缺失、文档状态与 `status` 字段矛盾、
挂载层与真实定义不同步、门禁引用了不存在的检查项。

**只读。** 不修改任何文件，包括不"顺手修复"——修复是人的决定。

这是纯脚本 Skill，**不调用模型**：一致性判定必须可复现，同一次输入必须给同一份清单。

## 为什么必须有它

知识库的腐化从不出现在单个文件里。设计文档把"每月一致性检查"列为防腐化三机制之一，
但 2026-10-20 的一次端到端演练发现：**卡点几乎全部落在跨域的接缝上**——
某个编号被 5 处引用却根本没有定义；文档写着"未实现"而 Skill 早已实现。

这两类问题的共同点是**单文件检查发现不了**。所以它是"每次改完就跑一次"，不是"每月想起来才跑"。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 仓库根目录 | 由 `CLAUDE.md` + `09_资产库/` 自动定位 | 是 | 两者都存在；否则拒绝执行 |
| 被测文件集 | 全库 `*.md` | 是 | 自动枚举，排除 `projects/`、`.claude/`、`.git/` 与 `docs/`（提案文档） |

无需任何参数。**调用者不需要知道检查项清单**——它自己知道该查什么。

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 问题清单 | 输出给调用者 | 按类别分组的 Markdown，每条含定位与原文 |
| 统计摘要 | 输出首行 | STD 条目数 / Skill 数 / 门禁检查项数 |
| 机读结果 | 输出给调用者（可选） | JSON，供 CI 消费 |

**不写任何文件。** 需要留档时由调用者自行落盘。

## 前置条件（不满足则拒绝执行）

- 仓库根可定位（`CLAUDE.md` 与 `09_资产库/` 同时存在）
- Python 与 PyYAML 可用（缺 PyYAML 时**拒绝执行并说明**，不要退化成"没检查就说通过"）

## 检查项（当前 7 类）

| # | 查什么 | 为什么它属于"接缝" |
|---|---|---|
| 1 | `STD-*` 条目悬空引用 | 条目可能只存在于别人的引用里 |
| 2 | Skill 名引用有效性 | 引用方与被引用方分属两个文件 |
| 3 | 三件套与 frontmatter 完整性 | 缺 `description` 会让该 Skill 不被任何会话发现 |
| 4 | 上下文预算超标 | 预算写在配置里，实际行数在另一个文件里 |
| 5 | 门禁引用的检查项都有实现 | 门禁定义与执行器是两个文件 |
| 6 | 文档状态描述与 `status` 字段矛盾 | 字段在一处，正文在另一处 |
| 7 | 挂载层与真实定义同步 | 挂载层是生成物，会悄悄过期 |

**检查项会随腐化方式增加。** 增加了哪些写在脚本里，不在这里复述——避免"两处清单需要同步"这种问题再生一层。

## 边界（明确不做）

- **不自动修复。** 只报告。修复涉及规范语义，必须由人决定
- 不检查条目正文的**语义**矛盾（如"这条规范与那条规范冲突"），只处理显式声明的关系
- 不检查 `docs/` 下的提案文档（设计文档与演练记录通篇是假设的编号与假想的反例）
- 不做 Markdown 渲染检查、不做拼写检查
- 不调用模型

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 查出问题 | 逐条列出（含文件、行号、原文片段），退出码 1 |
| 无问题 | 明确报"未发现跨文件不一致"，退出码 0 |
| 缺 PyYAML / 找不到仓库根 | 退出码 2，**说明缺什么**，不要静默跳过 |

**"没查出问题"不等于"没问题"。** 它只覆盖上表 7 类；报告"未发现不一致"时必须同时说明这一边界，
否则会被当成"整库已验证"——那比不检查更危险。

## 何时必须调用

- 改完任何规范条目、Skill 定义或门禁定义后
- 新增或重命名 Skill 后
- 重建挂载层后（`ai-spec-mount` 的下游）
- 发版前
- 怀疑文档与实现对不上时的第一动作

## 与其他 Skill 的关系

- 上游：无。它读全库，不依赖任何前置产出
- 下游：无。它是只读终点，产出的问题清单交由人处理
- 配套：改完规范跑 `ai-spec-build`，改完 Skill 跑 `ai-spec-mount`，然后跑本 Skill 收口
- 被调用：`ai-flow-autopilot` 在批次收尾时调用它
