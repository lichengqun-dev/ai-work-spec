# # 后端编码规范

## STD-BASE-401 · 语法级规范在规范包中，本文件只放跨栈共性

<!-- meta
tier: resident
scope: 规范分层
frozen: false
-->

**规则**：本文件只存放**跨技术栈**的后端规范。具体语法、框架用法、命名空间等与技术栈强相关的约束，一律放在 `09_资产库/规范包/stacks/be-*` 中，不写在这里。

**正例**：「事务内不得调用远程服务」写在本文件（跨栈共性）

**反例**：「Java 8 禁用 var」写在本文件（应放在 `be-springboot2-java8` 包）

**原因**：本 workspace 同时存在 Java 8 / 17 / 21 三个后端栈。把栈相关规范写进基线，会导致不适用的项目也被约束，或者需要在每个项目里禁用这条——两种结果都糟。

---

## STD-BASE-402 · 事务内不得调用远程服务

<!-- meta
tier: resident
scope: 事务边界
frozen: false
-->

**规则**：数据库事务内不得发起远程调用（HTTP / RPC / 消息发送）。需要跨系统一致性的场景，采用「先提交本地事务，再异步发起远程调用 + 失败补偿」。

**正例**：本地事务提交后发布事件，由监听器异步调用远程服务

**反例**：在 `@Transactional` 方法内直接调用外部接口，靠长事务保证一致

**原因**：远程调用耗时不可控，持有数据库连接与行锁的时长随之不可控，高并发下会迅速耗尽连接池。同时远程调用失败后事务回滚，但对方可能已经执行了副作用。

---

## STD-BASE-403 · 异常不得吞掉

<!-- meta
tier: indexed
scope: 异常处理
frozen: false
-->

**规则**：捕获异常后必须处理或向上抛出，不得空 catch 或仅打印日志后继续返回正常结果。

**正例**：记录日志并通过统一响应封装返回明确错误码

**反例**：`catch (Exception e) { log.error(...); }` 后返回 `null` 或空集合

**原因**：吞掉异常会把错误转变成「数据看起来不对」，排查时需要在整条链路上猜测是哪一步静默失败了。对调用方而言，「没有数据」和「查询失败」是完全不同的语义。

---

## STD-BASE-404 · 日志必须能串联同一次请求

<!-- meta
tier: indexed
scope: 日志规范
frozen: false
-->

**规则**：同一次请求链路中的日志必须携带同一个追踪标识（traceId），并在入口处生成、跨服务透传。

**正例**：网关生成 traceId，通过请求头透传，日志框架自动附加

**反例**：各服务各自打日志，靠时间戳人工对齐

**原因**：分布式环境下没有追踪标识就无法还原一次请求的完整路径，排障时间会成倍增加。
