# 前端编码规范

## STD-BASE-411 · 框架相关规范在规范包中

**规则**：本文件只放**跨框架**的前端共性规范。Vue / React 各自的具体约定放在对应技术栈包中。

**正例**：「接口请求统一走封装模块」写在本文件（跨框架共性）

**反例**：「必须使用 `<script setup>`」写在本文件（应放在 `fe-vue3-elementplus` 包）

**原因**：前端同时存在 Vue 2 / Vue 3 / React 三种栈，框架相关规范写进基线会产生大量误约束。

---

## STD-BASE-412 · 接口请求统一走封装模块

**规则**：所有 HTTP 请求通过项目封装的请求模块发起，组件内不得直接调用底层 HTTP 库。

**正例**：组件调用封装模块，由封装层统一处理鉴权、错误提示、加载态

**反例**：组件内直接 import 底层 HTTP 库并发起请求

**原因**：封装层统一承担了鉴权头注入、错误提示、加载态、隔离参数等横切逻辑。绕过封装会导致鉴权丢失或数据越权，而且这类缺陷在联调阶段很难暴露——接口能通，只是返回了不该看到的数据。

---

## STD-BASE-413 · 面向用户的文案不得硬编码

**规则**：面向用户的文案集中管理（i18n 资源或统一文案常量），不在组件模板中散落硬编码字符串。

**正例**：文案走 `$t()` 或集中常量文件

**反例**：模板里直接写中文

**原因**：硬编码文案在需要多语言、需要统一改口径（如产品改名）时会造成全项目返工，而且这类问题通常到测试后期才发现。
