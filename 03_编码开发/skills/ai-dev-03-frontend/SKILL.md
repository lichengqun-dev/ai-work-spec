# 能力声明

依据**冻结契约**与前端设计实现前端页面，从原型工程迁移，基于契约联调。

技术细节从生效规范快照读——换技术栈不需要重写本 Skill。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 接口契约 | `ai-design-04-api` 产出 | 是 | **冻结态**；哈希须与记录一致 |
| 前端设计 | `ai-design-05-frontend-spec` 产出 | 是 | 含页面清单、组件拆分、状态流转、接口映射 |
| 原型工程 | `ai-requirement-03-prototype` 产出 | 是 | 带 `data-fn` 标记 |
| 生效规范快照 | `.ai/spec-effective/<项目码>.md` | 是 | 前端规范与组件约定的唯一来源 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 前端代码 | 项目代码仓 | 按 FN 分次提交，提交信息含 FN 编号 |

## 前置条件（不满足则拒绝执行）

- gate-03 已通过，契约处于冻结态，且哈希与记录一致
- 前端设计已产出，页面与接口的映射关系明确
- 生效快照中的前端规范包存在

## 执行步骤

1. 从原型工程迁移页面结构（**迁移而非重画**——原型是业务方已确认过的形态）
2. 按前端设计的接口映射接入契约中的接口
3. 应用前端设计标注的状态归属（服务端状态用请求层管理，**不进全局 store**）
4. 补齐异常态与空态的呈现
5. 提交，提交信息格式：`feat(FN-XXX-000): <描述>`
6. 下一个 FN 或页面

## 边界（明确不做）

- **不改契约。** 联调发现接口不够用 → 停止并说明需要变更子批次
- 不改原型（原型是已确认的形态，改动需回到 `ai-requirement-03-prototype`）
- 不做后端实现（`ai-dev-02-backend`）
- 不做视觉设计（配色、图标、动效）——除非前端设计明确要求
- 不重构与本 FN 无关的页面

## 与后端的关键差异

后端按 FN 交付，前端**按页面交付更自然**——一个页面对应多个 FN 是常态。

但提交信息仍须带 FN 编号：一个页面提交覆盖多个 FN 时，在 body 中列全：

```
feat(FN-CORE-045): 列表页导出入口与结果展示

覆盖 FN-CORE-045（导出入口）、FN-CORE-046（导出结果下载）
```

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 契约哈希不一致 | **停止**，报告契约被改动过 |
| 原型中某页面缺 `data-fn` 标记 | 列出，回到 `ai-requirement-03-prototype` 补齐，**不凭印象实现** |
| 契约字段不足以支撑页面 | 停止并说明需要变更子批次 |
| 快照未覆盖的组件用法 | 停下问用户，不自行决定 |
| 需要引入新的前端依赖 | 停止并说明，走确认流程 |
