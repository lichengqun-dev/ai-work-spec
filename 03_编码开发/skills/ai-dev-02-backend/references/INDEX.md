# 知识索引 · ai-dev-02-backend

> `references/` 默认**只加载本文件**。按下方「何时读取」按需读取，单次不超过 3 个文件、合计 1500 行。
> **本文件内的路径**：`references/` 开头的是本 Skill 内的资源；「知识库根下」开头的是 Skill 之外的资源。

**本 Skill 不硬编码任何框架写法**——技术细节全部从生效规范快照读。
所以本目录几乎没有独立知识文件，这是刻意的设计。

| 知识 | 位置 | 何时读取 |
|---|---|---|
| 实现纪律要点（一次一个 FN、不改契约、不重构无关代码、密钥判读） | `references/实现纪律要点.md` | 想"顺便多做一点"时 |
| 后端通用基线（跨技术栈） | 知识库根下 `03_编码开发/standards/后端编码规范.md` | 每次开始前 |
| **技术栈具体写法** | 知识库根下 `09_资产库/规范包/stacks/be-*` | **每次实现前按需检索**（查哪条由生效快照 B 段的触发场景决定） |
| 数据库方言 | 知识库根下 `09_资产库/规范包/stacks/db-*` | 写查询时 |
| 各门禁会被校验的形式 | 知识库根下 `07_质量门禁/skills/ai-gate-runner/references/检查项清单.md` | 提交前 |

## 什么时候该在本目录新增文件

- **规范包未覆盖、但这个项目反复遇到的实现陷阱**（先放这里观察，出现 ≥3 个项目再提升为包条目）
- 本项目的分层落点约定（哪个模块放 Service、哪个放 Mapper）
- 历次代码评审中反复出现的问题

**注意**：技术栈相关的写法**不要写在这里**，要写进规范包。
写成项目级文件会让换栈时无法复用，而那正是"Skill 保持技术中立"要避免的。
