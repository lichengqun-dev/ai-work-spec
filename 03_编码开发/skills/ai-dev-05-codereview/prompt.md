# 指令：执行代码评审

## 你要做的事

```bash
S=07_质量门禁/skills/ai-gate-runner/scripts/gate_run.py
python3 $S --project <项目码> --batch <批次号> --gate gate-04
```

跑之前先确认 `projects/<项目码>/project.yaml` 的 `repo` 填了真实路径——
没填的话密钥扫描与提交检查都会记 `skip`，等于这两项没查。

## 跑完之后逐条读输出

**不要总结成"评审已完成"，逐条转达：**

| 输出 | 你该做什么 |
|---|---|
| `✅ pass` | 无需处理 |
| `❌ fail` | **原样读出明细**——执行器已给出提交哈希或文件行号，直接转达 |
| `⏭️ skip` | 连同"要做什么才能自动校验"一起读出。**`skip` 不是通过** |
| 人工核对清单 | 原样列出，**不替用户判断** |

## 最容易被跳过的是人工项

gate-04 的自动项只有 5 项，人工项也有 5 项。**自动项全绿不代表可以签核。**

特别是「实际实现的接口签名与冻结契约一致」这一项——执行器只能校验契约文件自身，
实现是否遵循契约需要读代码。**它是"联调时才发现对不上"的唯一前置拦截点**，
如果这里也跳过，那道门禁就形同虚设。

用户说"自动化都过了，直接签核吧"时，**提醒他人工项的清单还没核对**，
把清单再列一遍，让他明确回答每一项的结论。

## 提交信息不合规时

执行器会报具体是哪个提交、哪里不符（如"abc1234『update』类型或格式不符"）。

**正确的修法**：改提交信息（`git commit --amend` 或 rebase 改历史），然后重跑门禁。

**不要做的事**：
- 不要建议用 `--no-verify` 绕过 commit hook
- 不要建议把校验从门禁定义里删掉
- 不要说"这次先这样，下次注意"

## 密钥告警时

`secrets-externalized` 是 BLOCK 级，会报出具体文件与行号。处理方式：

1. 把值改为占位符或配置中心引用
2. **如果这个值已经提交进历史，它就已经泄露了** —— 必须轮换密钥，改当前版本没用
（Git 历史、fork、本地副本都还留着）

明确告知这一点，不要说成"改掉就好了"。

## 签核

```bash
python3 $S --project <项目码> --batch <批次号> --gate gate-04 --confirm --by <真实人名>
```

`--by` 填 `auto`、`admin` 之类等于没留痕——门禁记录的价值在于能回答"谁在什么时候确认的"。

## 你绝对不要做的事

- **不要代替人判断人工检查项**，特别是契约一致性那一项
- **不要把 `skip` 说成通过**
- **不要为让门禁通过而改门禁定义、改状态文件、改提交历史以掩盖问题**
- **不要建议绕过 commit hook**
- **不要自己改代码来消除失败项**（发现问题应回到实现 Skill 重做）
- 不要执行 git 操作

## 输出格式

```
门禁：gate-04 代码评审
批次：PROJ-20261020-001
结果：failed

【自动检查】
✅ [1] 提交信息符合格式
✅ [2] 每个 FN 都有对应的代码提交
✅ [3] 新增配置 / 密钥是否外置
⏭️  [4] 编码静态检查 —— skip（需在项目仓执行 lint）
⏭️  [5] 单元测试覆盖率 —— skip（需项目侧生成报告）

【需人工核对】5 项，执行器不替你拍板
- [6] 实际实现的接口签名与冻结契约一致
- [7] 无 N+1 查询、无循环内远程调用
- [8] 涉及核心数据写入的改动是否走统一入口
- [9] 事务内是否发起远程调用
- [10] 异常是否被吞掉

下一步：核对上表 5 项后签核；静态检查与覆盖率需在项目仓执行后人工确认。
```
