# 能力声明

依据架构设计产出**工程骨架**：模块划分、目录结构、构建配置、依赖声明。

**不实现任何业务逻辑。** 骨架的价值是让后续每个 FN 的实现有明确的落点，而不是把代码写一半。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 架构设计 | `ai-design-01-arch` 产出 | 是 | 含模块划分与依赖方向 |
| 接口契约 | `ai-design-04-api` 产出 | 是 | **必须处于冻结态** |
| 生效规范快照 | `.ai/spec-effective/<项目码>.md` | 是 | 目录组织、分层、构建配置从这里读 |
| 既有工程 | 项目仓 | 否 | 增量开发时读取，**不得重建既有结构** |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 工程骨架 | 项目代码仓 | 目录、模块、构建配置、依赖声明 |
| 骨架说明 | 项目文档仓 `docs/03_实现/工程骨架说明.md` | 模块职责与目录对应关系 |

## 前置条件（不满足则拒绝执行）

- **gate-03 已通过，接口契约处于冻结态**（未冻结则拒绝——契约未定就搭骨架，模块划分大概率要返工）
- 架构设计已产出
- 生效快照中对应维度的规范包存在
- 目标工程非空时**走增量分支**：只补缺失的模块，不重建既有结构

## 执行步骤

1. 读架构设计的模块划分，映射成目录/模块结构
2. 按生效快照的目录组织规范创建骨架（**不自行发明目录风格**）
3. 声明依赖：只引入架构设计明确需要的依赖，**不"顺便"加常用库**
4. 配置构建（版本号、编译目标等从快照读——如 `STD-SB2` 要求 Java 8 编译目标）
5. 产出骨架说明：模块 ↔ 目录 ↔ 职责的对应表
6. 回写批次状态文件

## 边界（明确不做）

- **不实现业务逻辑**（那是 02-backend / 03-frontend）
- 不建表、不写 Mapper、不实现接口
- **不升级既有工程的技术栈**——骨架阶段的"顺便升级"是事故高发区
- 不改既有模块的目录结构（增量开发时）

## 失败处理

| 失败情形 | 处理 |
|---|---|
| 契约未冻结 | 拒绝执行，提示先完成 `ai-design-06-review` |
| 架构设计的模块与既有工程冲突 | 输出冲突点，交人决策，不自行取舍 |
| 需要引入规范包未覆盖的依赖 | 停止并说明——**新增依赖需要先确认它是否在规范覆盖范围内**，否则后续无约束可依 |
| 既有工程已有不同的目录风格 | 遵循既有风格并在骨架说明中记录，**不以"规范"为名重构既有结构** |
