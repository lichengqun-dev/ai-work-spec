# info-security

承载**信息安全业务本身**的约束：审计留痕要求、数据分类分级、脱敏规则、外部合规要求。

## 本包目前为空，且必须由业务负责人填充

**写错的信息安全约束比没有约束更糟**——它会让团队以为已经合规。

技术侧凭常识拟定"看起来合理"的安全条款，会产生两个后果：一是可能遗漏真实要求，
二是团队会因为"规则已经写好了"而停止追问，真实要求反而更难被发现。

## 与 platform-base 的边界

这两个包容易被混为一谈，但 Owner 不同：

| 关注点 | 归属 |
|---|---|
| 平台怎么做鉴权、怎么做数据隔离 | `platform-base`（技术侧，平台负责人） |
| 业务上哪些数据算敏感、留痕要留多久 | `info-security`（业务侧，业务负责人） |

一句话区分：前者管"网关怎么校验凭证"，后者管"审计日志必须保留多久"。

## 待确认清单（需业务负责人逐条确认）

- [ ] 审计留痕要求：哪些操作必须留痕、留痕字段、保留期限
- [ ] 数据分类分级标准：哪些字段属于敏感数据、分级依据
- [ ] 脱敏规则：展示、导出、日志三个场景各自的脱敏要求
- [ ] 外部合规要求：是否有等保或行业合规的硬性条款需转化为开发约束
- [ ] 数据出境与跨租户访问限制
