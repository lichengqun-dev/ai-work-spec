# 编码规范 · be-springboot3-java17

## STD-SB3-001 · 使用 `jakarta.*` 命名空间

**规则**：Servlet、Validation、Persistence、Annotation 等 API 使用 `jakarta.*` 包路径。

**正例**：`import jakarta.servlet.http.HttpServletRequest;`　`import jakarta.validation.Valid;`

**反例**：`import javax.servlet.http.HttpServletRequest;`

**原因**：Spring Boot 3 基于 Jakarta EE 9+。从 Spring Boot 2.6 项目迁移或参考老代码时，这是最常见的错误来源——编译可能通过（残留的 `javax` 传递依赖），运行期才报 `NoClassDefFoundError`。

**例外**：无。

---

## STD-SB3-002 · 跨项目复用代码以下限版本为准

**规则**：项目内部可自由使用 `var`、`record`、文本块、`switch` 表达式、模式匹配。但**计划跨项目复用**的代码（公共库、工具类）不得使用 Java 17 以上才有的特性。

**正例**：项目内部 DTO 用 `record`；公共工具类用传统 class。

**反例**：把用了 Java 21 模式匹配或虚拟线程的工具类复制到 Java 17 项目。

**原因**：本 workspace 同时存在 Java 8 / 17 / 21 三个后端栈。跨项目复用的代码若依赖高版本特性，复制即编译失败。

---

## STD-SB3-003 · 禁止引入 N+1 查询

**规则**：循环体内不得调用 Mapper / Repository 查询。列表场景使用批量查询（`IN`）或关联查询一次取回。

**正例**：`selectByIds(ids)` 一次取回后在内存分组组装。

**反例**：循环内逐条 `selectById`。

**原因**：小数据量下无感知，上线后随数据增长暴露为接口超时。

---

## STD-SB3-004 · 分页查询必须设上限

**规则**：列表查询的 `pageSize` 必须有服务端上限（建议 200），不信任前端传值。

**正例**：`pageSize = Math.min(pageSize, MAX_PAGE_SIZE)`

**反例**：前端传值直接进分页对象。

**原因**：`pageSize` 过大会导致全量加载与 OOM。

---

## STD-SB3-005 · 跨服务调用必须设置超时与故障隔离

**规则**：所有远程调用显式设置连接/读取超时；关键链路配置熔断或降级，失败时记录补偿信息。

**正例**：超时 + 熔断器 + 失败补偿记录。

**反例**：依赖框架默认值（部分客户端默认无限等待）。

**原因**：下游卡住时无超时的调用会耗尽线程池，把单点故障放大为级联故障。
