# 编码规范 · fe-react-antd

## STD-REACT-001 · 只写函数组件 + Hooks

<!-- meta
tier: resident
scope: 组件写法
frozen: false
-->

**规则**：所有组件使用函数组件 + Hooks，不新增 class 组件。

**正例**：`export default function AgentList() { … }`

**反例**：`class AgentList extends React.Component { … }`

**原因**：class 组件无法使用 Hooks，会导致状态逻辑无法在组件间复用；且与 React 18 的并发特性配合不佳。

---

## STD-REACT-002 · 服务端状态与客户端状态分离

<!-- meta
tier: resident
scope: 状态管理
frozen: false
-->

**规则**：来自接口的数据（服务端状态）用请求 hook 管理，组件卸载即释放；只有真正的客户端状态（UI 开关、选中项、表单草稿）才放进全局 store。

**正例**：列表数据由 `useAgentList()` 之类的 hook 承载。

**反例**：把接口返回的列表塞进全局 store，各页面从中读取。

**原因**：服务端状态放进全局 store 后，缓存失效、竞态、重复请求都要手工处理，且容易出现"两个页面看到同一份过期数据"。这是 React 项目最常见的状态管理债务。

## STD-REACT-003 · antd 主题通过 ConfigProvider 统一配置

<!-- meta
tier: indexed
scope: 主题与样式
frozen: false
-->

**规则**：主题 token 在应用根部 `ConfigProvider` 统一配置，不在组件内用行内 `style` 覆盖 antd 的间距、颜色、圆角。

**正例**：根部 `<ConfigProvider theme={{ token: { colorPrimary: '#1677ff' } }}>`

**反例**：`<Button style={{ background: '#1677ff', borderRadius: 8 }}>`

**原因**：antd 5 使用 design token 体系，行内覆盖会绕开它，导致暗色模式、紧凑模式、RTL 布局等全局能力失效。

## STD-REACT-004 · 画布类组件不持有业务数据

<!-- meta
tier: indexed
scope: 图与画布
frozen: false
-->

**规则**：使用画布/流程图类库时，画布只持有布局与视图状态；节点与边的业务数据由外部数据源提供，通过 props 或受控接口注入。

**正例**：业务数据 → 转换函数 → 画布 nodes/edges；画布只回传位置变更事件。

**反例**：把接口返回的业务对象直接塞进 `nodes[].data` 并在画布内部修改。

**原因**：画布库的内部状态机与业务数据模型耦合后，"保存布局"与"保存业务数据"会互相污染，撤销/重做也无法可靠实现。
