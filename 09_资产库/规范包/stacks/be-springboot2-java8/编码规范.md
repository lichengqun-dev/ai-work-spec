# 编码规范 · be-springboot2-java8

## STD-SB2-001 · 禁止使用 Java 9+ 语法

<!-- meta
tier: resident
scope: 语言级约束
frozen: false
-->

**规则**：源码必须能通过 Java 8 编译。不使用 `var`、`record`、文本块（`"""`）、`switch` 表达式、`instanceof` 模式匹配、`List.of()` / `Map.of()` / `Stream.toList()` 等 9+ 才有的 API。

**正例**：
```java
Map<String, Object> params = new HashMap<>();
List<String> ids = list.stream().map(Item::getId).collect(Collectors.toList());
```

**反例**：
```java
var params = new HashMap<String, Object>();                   // Java 10
List<String> ids = list.stream().map(Item::getId).toList();    // Java 16
String sql = """SELECT * FROM t""";                            // Java 15
```

**原因**：本栈 `maven.compiler.source/target = 1.8`，上述语法**编译期直接失败**。AI 生成代码时默认倾向现代语法，是本栈最高频的返工来源。

**例外**：无。这是编译约束，不是风格偏好。

## STD-SB2-002 · 使用 `javax.*` 而非 `jakarta.*` 命名空间

<!-- meta
tier: resident
scope: 依赖与命名空间
frozen: false
-->

**规则**：Servlet、Validation、Persistence、Annotation 等 API 使用 `javax.*` 包路径。

**正例**：`import javax.servlet.http.HttpServletRequest;`　`import javax.validation.Valid;`

**反例**：`import jakarta.servlet.http.HttpServletRequest;`

**原因**：Spring Boot 2.6 基于 `javax.*`；`jakarta.*` 是 Spring Boot 3 / Jakarta EE 9+ 的命名空间。混用会导致 `NoClassDefFoundError`，而且**往往编译能过**（IDE 里可能残留传递依赖），到运行期才暴露。

**例外**：无。

## STD-SB2-003 · 禁止引入 N+1 查询

<!-- meta
tier: indexed
scope: 持久层
frozen: false
-->

**规则**：循环体内不得调用 Mapper / Repository 查询。列表场景使用批量查询（`IN`）或关联查询一次取回。

**正例**：先 `selectByIds(ids)` 一次取回，再在内存中按 id 分组组装。

**反例**：
```java
for (Long id : ids) {
    Item item = itemMapper.selectById(id);   // N 次查询
    result.add(convert(item));
}
```

**原因**：N+1 在小数据集下无感知，上线后随数据量增长才暴露为接口超时——而此时已经很难定位到具体是哪个循环。

## STD-SB2-004 · 分页查询必须设上限

<!-- meta
tier: indexed
scope: 分页
frozen: false
-->

**规则**：所有列表查询的 `pageSize` 必须有服务端上限（建议 200），且分页参数由服务端二次校验，不信任前端传值。

**正例**：`pageSize = Math.min(pageSize, MAX_PAGE_SIZE);`

**反例**：直接把前端传来的 `pageSize` 塞进分页对象。

**原因**：前端传 `pageSize=100000` 会导致全表加载 + OOM。这是一个**一句话就能防住、但后果很重**的缺陷。

---

## STD-SB2-005 · 跨服务调用必须设置超时

<!-- meta
tier: indexed
scope: 服务调用
frozen: false
-->

**规则**：所有远程调用（Feign / RestTemplate / HTTP 客户端）必须显式设置连接超时与读取超时，不使用框架默认值。

**正例**：`connectTimeout=2000, readTimeout=5000`

**反例**：依赖默认配置——部分客户端默认**无超时**，等同于无限等待。

**原因**：下游服务卡住时，无超时的调用会耗尽线程池，把单点故障放大为级联故障。
