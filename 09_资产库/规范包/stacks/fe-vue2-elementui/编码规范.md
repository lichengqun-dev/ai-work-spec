# 编码规范 · fe-vue2-elementui

## STD-VUE2-001 · 默认使用 Options API，不引入新的 Composition API 写法

**规则**：新增组件默认使用 Options API。项目虽安装了 `@vue/composition-api`，但不得在新增组件中主动使用。

**正例**：`export default { data() {…}, methods: {…} }`

**反例**：新增组件中 `import { ref } from '@vue/composition-api'`。

**原因**：该插件是历史上为个别组件引入的，未被全项目采用。混用会导致同一模块内两套写法并存，新人无法判断该跟随哪一种。

**例外**：修改既有使用 Composition API 的组件时，在同一文件内跟随既有写法，不得同一文件混用两种风格。

## STD-VUE2-002 · 同一页面内 UI 库同类组件不得混用

**规则**：同一功能场景只使用一套 UI 库的组件。项目同时存在 Element UI 与 ant-design-vue，两者功能重叠的部分必须在同一页面内指定唯一主库。

**正例**：页面内表格与弹窗统一用 `el-table` / `el-dialog`。

**反例**：同一页面里一半用 `el-table`、一半用 `a-table`。

**原因**：两套库的样式变量、尺寸体系、交互反馈不同。页面内混用会让视觉与交互不一致；同时增加打包体积与维护面。

**例外**：Element UI 缺失的能力允许使用另一套库，但需在组件顶部注释说明原因。

---

## STD-VUE2-003 · 大数据量表格必须使用虚拟滚动

**规则**：单次渲染行数可能超过 200 行的表格，必须使用虚拟滚动方案，不用 `el-table` / `a-table` 直接渲染全量数据。

**正例**：只读大列表启用虚拟滚动；批量编辑场景评估专用表格组件。

**反例**：`<el-table :data="allRows">` 直接绑定 5000 条数据。

**原因**：Element UI 的 table 不做虚拟滚动，大数据量下会产生数千个 DOM 节点，页面卡死。这类问题在开发机上数据少时不出现，上线后才暴露。

---

## STD-VUE2-004 · 接口请求统一走封装的 request 模块

**规则**：所有 HTTP 请求通过项目封装的 request 模块发起，组件内不得直接调用 `axios`。

**正例**：`import request from '@/utils/request'` 后调用。

**反例**：组件内 `import axios from 'axios'; axios.get('/api/…')`。

**原因**：封装层统一处理 baseURL、鉴权头、错误提示、加载态与隔离参数。绕过封装会导致鉴权丢失、错误无提示、数据隔离失效。
