# 编码规范 · fe-vue3-elementplus

## STD-VUE3-001 · 组件统一使用 `<script setup>` + TypeScript

<!-- meta
tier: resident
scope: 组件写法
frozen: false
-->

**规则**：所有 `.vue` 组件使用 `<script setup lang="ts">`，不写 `export default`，不使用 `setup()` 函数返回对象。

**正例**：
```vue
<script setup lang="ts">
const props = defineProps<{ id: string }>()
const emit = defineEmits<{ (e: 'change', v: string): void }>()
</script>
```

**反例**：使用 Options API；或在 `<script setup>` 里再写一个 `export default`。

**原因**：混用会让 props/emits 的类型声明方式不一致，`vue-tsc` 的类型检查也无法覆盖 Options API 写法的那部分，等于在类型体系上开了个洞。

**例外**：迁移中的老页面允许保留 Options API，但新增功能不得在同一文件内混用两种风格。

## STD-VUE3-002 · 组件内禁止直接调用 axios

<!-- meta
tier: resident
scope: 网络请求
frozen: false
-->

**规则**：所有 HTTP 请求走项目封装的 request 模块（`src/utils/request` 或等价封装）。

**正例**：`import { request } from '@/utils/request'` 后调用。

**反例**：组件内 `import axios from 'axios'` 直接发请求。

**原因**：封装层统一处理 baseURL、鉴权头、租户/用户参数、错误提示与加载态。绕过封装会导致鉴权丢失或数据隔离失效，而这类缺陷在联调阶段很难暴露——接口能通，只是返回了不该看到的数据。

## STD-VUE3-003 · 状态管理使用 Pinia，且不在组件内直接改 state

<!-- meta
tier: indexed
scope: 状态管理
frozen: false
-->

**规则**：跨组件共享状态使用 Pinia store；组件内通过 action 修改状态，不直接对 store 的 state 赋值。

**正例**：`const store = useUserStore(); store.setCurrentUser(u)`

**反例**：`const store = useUserStore(); store.currentUser = u`

**原因**：直接改 state 会绕过 action 中的副作用（持久化、联动刷新、埋点）。允许直接赋值等于允许状态在任意位置被改，排查问题时无法定位变更来源。

**例外**：纯展示用的临时 UI 状态（弹窗开关、tab 选中项）放组件本地 `ref`，不要进 store。

## STD-VUE3-004 · 国际化文案必须走 vue-i18n，禁止硬编码中文

<!-- meta
tier: indexed
scope: 文案与国际化
frozen: false
-->

**规则**：面向用户的文案通过 `$t()` / `t()` 获取，不在模板或脚本中硬编码中文字符串。

**正例**：`<el-button>{{ $t('common.confirm') }}</el-button>`

**反例**：`<el-button>确定</el-button>`

**原因**：硬编码文案在切语言时会残留中文，而这类问题通常到测试后期才被发现，返工面很大——它散落在大量文件里。

**例外**：控制台日志、代码注释不受此约束。

## STD-VUE3-005 · 表单校验规则集中定义

<!-- meta
tier: indexed
scope: 表单
frozen: false
-->

**规则**：表单校验规则定义在 `<script setup>` 中的 `rules` 常量里，不写成模板的 `:rules` 内联对象。

**正例**：
```vue
<script setup lang="ts">
const rules = { name: [{ required: true, message: '请输入名称', trigger: 'blur' }] }
</script>
<template><el-form :model="form" :rules="rules">…</el-form></template>
```

**反例**：直接在模板里 `:rules="{ name: [{ required: true }] }"`。

**原因**：内联写法在字段变多后无法维护，且规则无法被单测覆盖、无法复用（新增与编辑场景通常共用同一套规则）。
