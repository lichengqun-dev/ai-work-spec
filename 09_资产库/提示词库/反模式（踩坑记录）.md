# 反模式（踩坑记录）

> 记录**已经踩过**的坑。每条都要有具体的失败案例，不要收录推测性的"可能有问题"的情况。

## 待填充

格式：

```markdown
## 反模式：<一句话描述>

**表现**：<做的时候是什么样>
**后果**：<造成了什么实际损失>
**纠正**：<后来怎么改的>
**发生批次**：<批次号>（有据可查比"据说"有价值得多）
```

## 已知需要警惕的方向

以下是从设计阶段就预见到的风险，**待在真实批次中验证后再正式收录**：

- Skill 臃肿化：每次遇到例外就顺手加一条，最终无人敢改
- 上下文全量注入：怕 AI 不知道，把什么都塞进去
- 门禁全自动阻断：没有豁免通道，团队整体关闭门禁
- 文档与代码脱节：文档只在开始时写一次
- 产出物不编号：追溯链从第一天就是断的

这些写在设计方案里，但**没有本团队的真实案例前，它们只是外部经验**。
