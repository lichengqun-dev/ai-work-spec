## 门禁设计的三个要点

**一、自动检查优先，人工检查兜底。** 每个检查项先问"能不能写成脚本"。能写的一律自动化——因为人工检查会随时间推移变成走过场。只有真正需要判断力的（技术方案是否合理、索引设计是否恰当）才留给人。

**二、区分 BLOCK 与 WARN。** 如果所有检查项都是阻断项，团队会在第一次被卡住后要求关闭整道门禁。区分级别让门禁具备"可存活"性——WARN 项生成待办但不阻断，让团队感受到门禁在帮忙而不是添乱。

**三、豁免要留痕，且自动复查。** 任何门禁都要有豁免通道（紧急上线是客观现实），但豁免必须写进批次状态文件并自动在 7 天后生成复查提醒。**没有自动复查的豁免机制，等于没有门禁。**

## 三道不可豁免的门禁

gate-02（原型确认）、gate-06（归档交付）完全不可豁免；gate-03 / 04 的契约一致性项、gate-05 的 P0/P1 缺陷项不可豁免。

这几道之所以不留口子，是因为它们各自守着一个**跳过就无法补救**的东西：需求理解、追溯链完整性、契约唯一事实源、质量底线。其余门禁留通道，是为了让团队在整体上愿意保留门禁。
