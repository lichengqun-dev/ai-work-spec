# 门禁检查脚本

**本目录当前为空。** 门禁的自动检查项不放在这里，而是实现在执行器的检查项库里：

```
07_质量门禁/skills/ai-gate-runner/scripts/gate_run.py
```

## 为什么不在这个目录放脚本

最初的设计是"每个 `auto` 检查项对应一个独立脚本"，实际实现时改成了**单文件检查项库**，原因有三个：

**共享上下文。** 绝大多数检查项都要读同一批东西——批次状态文件、编号总表、产出物文本、项目仓 git log。独立脚本意味着每个都要自己解析一遍，或者依赖一个共享的中间产物（多一层失败点）。

**一致性。** 读取产出物、解析编号、判断路径归属这些逻辑必须完全一致，否则同一个 FN 在覆盖率检查里算"存在"、在断链检查里算"缺失"。放在一起才不可能分叉。

**`skip` 语义要统一。** "缺材料时记 skip 而不是 fail"是执行器级别的语义，散落在独立脚本里无法保证一致。

## 扩展方式

在 `gate_run.py` 中用装饰器注册：

```python
@check("my-check-id", "这个检查项校验什么")
def _c_my_check(ctx: Ctx):
    if (s := _need_docs(ctx)):        # 缺材料时统一返回 skip
        return s
    ...
    return (PASS, "通过了，附上证据")
    # 或 (FAIL, "具体哪个对象不达标")   —— 失败信息必须可定位
    # 或 (SKIP, "为什么查不了，以及要做什么才能查")
```

然后在门禁定义里引用：`| 3 | ... | auto:my-check-id | WARN | ... |`

最后必须跑一遍：

```bash
python3 gate_run.py --list-checks    # 确认没有"被引用但未实现"的项
```

## 硬性要求

1. **返回三态，不要返回布尔值。** `SKIP` 必须与 `FAIL` 区分开——把"没法校验"当成"不通过"会造成误报阻断，当成"通过"会让门禁失效。
2. **失败信息必须可定位。** 不能只打印"检查未通过"，要给出具体对象（哪个 FN / 哪个接口 / 哪个文件第几行）。
3. **只读且幂等。** 检查项不改被检查的对象，可重复执行。
4. **异常不能变成通过。** 检查项抛异常时执行器记为 `fail` 并附异常信息，不允许伪装成 pass。
