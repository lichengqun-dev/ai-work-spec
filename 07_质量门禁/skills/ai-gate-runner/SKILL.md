# 能力声明

统一的门禁执行器。读取 `07_质量门禁/gates/*.md` 的定义，执行其中的检查项，把结果写入批次状态文件。

**为什么要有统一执行器**：如果每道门禁各自实现检查逻辑，会出现三套问题——检查项的写法不一致（无法对比）、失败信息格式不一致（无法统一展示）、豁免机制各写各的（有的能豁免有的不能，且没人记得住）。

## 输入契约

| 输入 | 来源 | 必需 | 校验规则 |
|---|---|---|---|
| 门禁定义 | `07_质量门禁/gates/gate-*.md` | 是 | 含 stage / blocking / auto_check 字段与检查项表格 |
| 批次状态文件 | `.ai/state/<批次号>.yaml` | 是 | `current_step` 与 `gates` 段存在 |
| 生效规范快照 | `.ai/spec-effective/<项目码>.json` | 是 | 用于确认被检查的规范版本 |
| 待检查产出物 | 项目文档仓 | 是 | 按门禁定义逐项定位 |

## 产出契约

| 产出 | 路径 | 格式 |
|---|---|---|
| 门禁执行结果 | 批次状态文件 `gates` 段 | passed / failed / waived + 时间 + 执行者 |
| 失败明细 | `.ai/logs/<批次号>.jsonl` | 追加 JSON 行，含失败项与定位 |
| 待办清单 | `.ai/index/门禁待办.md` | WARN 项汇总 |

## 前置条件（不满足则拒绝执行）

- 门禁定义文件存在且可解析（检查项表格列数正确）
- 批次状态文件存在且 `current_step` 与门禁的 `stage` 匹配
- **上一道 gate 状态为 `passed` 或 `waived`**（不允许跳门禁）

## 执行步骤

1. 定位当前批次应执行的门禁（依据 `current_step`）
2. 逐项执行 `方式=auto` 的检查（调用 `scripts/` 下对应脚本）
3. 输出 `方式=人` 的检查项作为人工清单，等待确认
4. 汇总结果：BLOCK 项任一失败 → 门禁不通过
5. WARN 项写入待办清单，不阻断
6. 把结果写回批次状态文件（含执行时间与执行者）

## 边界（明确不做）

- **不自动修复。** 检查失败只报告，不尝试修正代码或文档
- 不代替人做 `方式=人` 的判断。它只负责把清单摆出来
- 不自动豁免。豁免必须由人显式写入，且带 `expires`
- 不修改门禁定义文件

## 失败处理

| 失败情形 | 处理 |
|---|---|
| BLOCK 项失败 | 门禁状态置 `failed`，产出物不可进入下一阶段，输出失败明细与定位 |
| 门禁定义文件格式错误 | 拒绝执行并报错（不允许"跳过无法解析的检查项"） |
| 上一道门禁未通过 | 拒绝执行，提示先完成上一道 |
| WARN 项失败 | 记录待办，门禁仍可通过 |
